    第9回　音声認識システムの構成要素と評価指標（WER, CER, SLUEベンチマーク）¶

    この回の資料

    • 📊 スライドを開く（HTML）
    • 📄 スライド（PDF）
    • 形式：動画回（オンデマンド動画＋CBTテスト）

    本日の到達目標¶

    1. 音声認識システムの全体構成を整理し、各要素の役割を説明できる
    2. WERとCERを数式に基づいて正確に計算できる
    3. 編集距離（Levenshtein距離）とWER/CERの関係を理解する
    4. SLUEベンチマークの概念を理解し、評価指標の使い分けを説明できる
    5. 発展：WERが編集距離を正解語数で割ったものであること、そしてWERが100%を超えうることを、式から自分で導ける

    進化の視点：何を「誤り」と数えるかが、評価を決める¶

    WER は書き起こしとの編集距離で誤りを数える。ではヒトの書き起こしはどうか。人間どうしでも書き起こしは完全には一致せず、雑音下では誤る。「人間並み」と言うときは、この人間側の誤り率を基準にしている。

    ヒトの強みは、雑音や複数話者の中で目的の声を追える点にある（カクテルパーティ効果、第2回）。耳が2つあること、口の動きを見ること、文脈を予測に使うことが組み合わさった結果である。

    技術への接続：評価指標を変えると、良いモデルの定義が変わる。単語単位か文字単位か、雑音下の条件を含めるか、話者が重なる状況を含めるか。ベンチマークの設計は、何を模倣したいのかの宣言でもある。

    問い：あなたの作るシステムでは、どんな誤りが致命的か。

    なぜ評価が重要か¶

    • モデルを改良したとき、本当に良くなったか？を客観的に測る
    • 異なるシステムを公平に比較する
    • 誤りのパターンを把握し、次の改善の方向性を決める

    スライド2: 音響モデル（AM）の役割と種類¶

    音響モデルの役割¶

    入力: 音声の特徴量列（フレームごとのベクトル）
    出力: 各フレームが各音素・文字である確率

    \[P(\text{音素} \mid \mathbf{o}_t) \quad \text{または} \quad P(\text{文字} \mid \mathbf{o}_1, \ldots, \mathbf{o}_T)\]

    音響モデルの種類と進化¶

    世代 モデル 特徴 典型的な性能（LibriSpeech）
    第1世代 GMM-HMM 確率モデル。MFCCを入力 WER〜7〜10%
    第2世代 DNN-HMM DNNで出力確率を計算 WER〜4〜6%
    第3世代 End-to-End（CTC, AED） アライメント不要 WER〜2〜4%
    第4世代 自己教師あり+微調整 少量ラベルで高性能 WER〜1〜3%
    現在 Whisper等大規模学習 多言語・ロバスト WER〜2〜4% (汎用)

    ファインチューニング後の活用¶

    第7回で学んだwav2vec 2.0やHuBERTは、音響モデルの初期化として使われる。事前学習→ファインチューニングの流れが現在の主流。

    スライド3: 言語モデル（LM）の役割¶

    言語モデルの役割¶

    音響モデルが出力する「音響的に尤もらしい候補」から、「言語的に自然な文」を選ぶ役割。

    \[P(W) = P(w_1, w_2, \ldots, w_L)\]

    N-gramモデル（従来）¶

    マルコフ仮定により、前\(N-1\)単語だけで次の単語を予測：

    \[P(w_t \mid w_1, \ldots, w_{t-1}) \approx P(w_t \mid w_{t-N+1}, \ldots, w_{t-1})\]

    例（trigram, \(N=3\)）:

    \[P(\text{今日} \mid \text{は}, \text{天気}) \approx P(\text{今日} \mid \text{は}, \text{天気})\]

    ニューラル言語モデル（現代）¶

    Transformer言語モデル（GPT系）により、長距離の文脈を考慮した予測が可能。

    End-to-Endシステムでの扱い¶

    • CTCデコーダ: 外部言語モデルとシャロウフュージョン（浅い統合）
    • Attention-based Decoder: デコーダ自体が内部言語モデルを学習
    \[\log P(Y \mid X) = \log P_{\text{AM}}(Y \mid X) + \lambda \log P_{\text{LM}}(Y)\]

    \(\lambda\) は言語モデルのウェイト（ハイパーパラメータ）。

    スライド4: デコーダの役割（ビーム探索）¶

    デコーダの役割¶

    AM確率とLM確率を組み合わせて、最も尤もらしいテキスト列を探索する。

    \[\hat{Y} = \arg\max_Y \left[\log P_{\text{AM}}(Y \mid X) + \lambda \log P_{\text{LM}}(Y)\right]\]

    貪欲探索（Greedy Search）¶

    各時刻で最も確率の高い文字を選ぶ。簡単だが最適解とは限らない。

    t=1: a(0.7), b(0.2), c(0.1) → "a"を選ぶ
t=2: b(0.6), c(0.3), a(0.1) → "b"を選ぶ
...
結果: "ab..." （局所最適）

    ビーム探索（Beam Search）¶

    上位\(B\)個（ビーム幅）の候補を常に保持しながら探索。

    ビーム幅 B=3 の例:

t=1: 上位3候補を残す
  "a"(0.7), "b"(0.2), "c"(0.1)

t=2: 各候補を展開 → 9候補 → 上位3を残す
  "ab"(0.7×0.6=0.42), "ac"(0.7×0.3=0.21), "ba"(0.2×0.5=0.10), ...

...

最終: 最もスコアが高い系列を出力

    直感: 探索の網を広げることで、貪欲法よりも良い解を見つけやすい。ただし\(B\)が大きいほど計算コストも増大。

    スライド5: 評価指標 — WER（Word Error Rate）¶

    WERの定義¶

    音声認識の最も基本的な評価指標。単語レベルの誤り率。

    \[\text{WER} = \frac{S + D + I}{N} \times 100\%\]

    ここで: - \(S\)（Substitutions）: 置換 — 正解単語が別の単語に認識された数 - \(D\)（Deletions）: 削除 — 正解単語が認識されなかった（消えた）数 - \(I\)（Insertions）: 挿入 — 存在しない単語が認識に現れた数 - \(N\): 正解文の総単語数

    注意: \(\text{WER} > 100\%\) になることもある（挿入が多い場合）。

    計算例1¶

    内容
    正解文 今日 は 天気 が いい
    認識結果 今日 は 天候 いい

    単語ごとに対応を確認:

    正解:   今日  は  天気  が  いい
認識:   今日  は  天候      いい

差分:
  今日 → 今日  (正解)
  は   → は    (正解)
  天気 → 天候  (置換: S+1)
  が   → (なし) (削除: D+1)
  いい → いい  (正解)
    \[S=1, \quad D=1, \quad I=0, \quad N=5\]
    \[\text{WER} = \frac{1+1+0}{5} = \frac{2}{5} = 40\%\]

    計算例2（挿入あり）¶

    正解:   今日  は  晴れ
認識:   今日  は  今日  は  晴れ

差分: 「今日 は」が挿入された
  S=0, D=0, I=2, N=3
    \[\text{WER} = \frac{0+0+2}{3} = \frac{2}{3} \approx 66.7\%\]
    導出①：\(S\)・\(D\)・\(I\) の3つで数え、正解語数で割る理由

    正解文を認識結果に「作り替える」と考える。使える操作は置換・削除・挿入の3つである。この3つがあれば、どんな語列からどんな語列へも必ず変換できる。 全部削ってから全部挿入すればよいからである。だから「変換できるか」ではなく「何回で変換できるか」が問題になり、その最小回数が誤りの量になる。これが次のスライドで扱う編集距離である。

    最適な対応づけのもとで、正解文の各単語は「一致・置換・削除」のいずれか1つに必ず分類される。したがって

    \[(\text{一致数}) + S + D = N\]

    同じように、認識結果の各単語は「一致・置換・挿入」のいずれかである。

    \[(\text{一致数}) + S + I = (\text{認識結果の語数})\]

    誤った箇所は \(S + D + I\) 箇所で、これが分子になる。

    なぜ分母が正解文の語数なのか。 誤りの絶対数は文の長さに比例して増えるので、そのままでは長さの違う文を比べられない。基準として固定されているのは正解文のほうである。認識結果の語数はシステムの出来によって変わるので、分母に使うと、同じ誤りでも出力を長くするほど見かけの誤り率が下がってしまう。テスト問題の選択肢に「1/5」があるのは、ここを取り違えていないかを問うためである。

    使った数学：場合分けによる数え上げ。

    導出②：なぜ WER は 100% を超えうるのか

    導出①の2つの式を引き算する。\((\text{一致数}) + S + D = N\) から \((\text{一致数}) + S + I = (\text{認識結果の語数})\) を引くと、一致数と \(S\) が消えて

    \[D - I = N - (\text{認識結果の語数})\]

    つまり

    \[I = (\text{認識結果の語数}) - N + D\]

    ここが要点である。 \(S\) と \(D\) は正解文の単語を分類したものなので \(S + D \leq N\) であり、この2つだけなら WER は 100% を超えない。ところが \(I\) は認識結果の語数に従って増え、上限が \(N\) と無関係である。認識結果をいくらでも長くできる以上、\(I\) もいくらでも大きくできる。

    数値で確かめる：正解文が はい（\(N=1\)）で、認識結果が はい はい はい（3語）のとき、一致数1、\(S=0\)、\(D=0\)、\(I = 3 - 1 + 0 = 2\) となり

    \[\text{WER} = \frac{0+0+2}{1} = 2 = 200\%\]

    「精度 ＝ 100 − WER」とは書けない

    WER は 0% から 100% のあいだに収まる量ではないので、100 から引いても「正解率」にはならない。WER は率という名前がついているが、確率ではなく比である。 上限がないことを知らずに「精度87%」などと書き換えると、意味の違う数字を報告することになる。

    同じ理由で、挿入が多く出るシステムは WER が極端に悪く出る。誤りの内訳（\(S\)・\(D\)・\(I\) の別）を見ずに WER だけを比べると、何が起きているか分からない。スライド10のエラー分析が必要なのはこのためである。

    使った数学：2つの数え上げの式の差を取る操作。

    スライド6: 編集距離（Levenshtein距離）との関係¶

    編集距離とは¶

    2つの文字列（または単語列）を一致させるために必要な最小操作回数。 操作は3種類: 置換（S）・削除（D）・挿入（I）。

    \[\text{WER} = \frac{\text{編集距離（単語レベル）}}{\text{正解の総単語数}}\]

    つまり、WERは単語列の（正規化）編集距離。

    動的計画法による計算¶

    \(\text{ref} = [r_1, r_2, \ldots, r_M]\)（正解）、\(\text{hyp} = [h_1, h_2, \ldots, h_N]\)（認識）とする。

    \(d[i][j]\): \(\text{ref}[1..i]\) と \(\text{hyp}[1..j]\) の編集距離

    漸化式:

    \[d[i][j] = \min\begin{cases} d[i-1][j] + 1 & \text{（削除: refのi番目を削除）} \\ d[i][j-1] + 1 & \text{（挿入: hypのj番目を挿入）} \\ d[i-1][j-1] + \mathbf{1}[r_i \neq h_j] & \text{（一致 or 置換）} \end{cases}\]

    初期条件: \(d[0][j] = j\), \(d[i][0] = i\)

    計算例（文字レベルでの例）¶

    ref = cat, hyp = car

    c a r
    0 1 2 3
    c 1 0 1 2
    a 2 1 0 1
    t 3 2 1 1

    編集距離 = 1（置換: t→r）

    導出③：なぜ表を埋めるだけで最小回数が求まるのか

    最小回数を素朴に求めようとすると、どの単語をどの単語に対応させるかの組み合わせをすべて試すことになり、長さとともに爆発する。動的計画法はこれを避ける。

    鍵は、\(d[i][j]\) を決めるのに必要なのは3つの小さい答えだけという点である。\(\text{ref}[1..i]\) と \(\text{hyp}[1..j]\) をそろえる最後の1手は、次の3通りしかない。

    • \(r_i\) を削除した　→ 残りは \(\text{ref}[1..i-1]\) と \(\text{hyp}[1..j]\) の問題、つまり \(d[i-1][j] + 1\)
    • \(h_j\) を挿入した　→ 残りは \(\text{ref}[1..i]\) と \(\text{hyp}[1..j-1]\) の問題、つまり \(d[i][j-1] + 1\)
    • \(r_i\) と \(h_j\) を対応させた　→ 残りは \(d[i-1][j-1]\) に、文字が違えば置換の1を足す

    最後の1手として可能なのはこの3つだけなので、最小値はこの3つの最小値になる。これが上の漸化式である。一致・置換・削除・挿入という誤りの種類が、漸化式の枝にそのまま対応している。

    初期条件 \(d[0][j] = j\) は「正解が空なら、認識結果の語数だけ挿入するしかない」ことを、\(d[i][0] = i\) は「認識結果が空なら、正解の語数だけ削除するしかない」ことを表している。

    表の大きさは \(M \times N\) で、各マスの計算は3つを比べるだけである。だから計算量は長さの積に比例する。上の cat と car の表は \(3 \times 3\) の9マスで、右下の 1 が答えである。

    第7回の前向きアルゴリズムと同じ構造である。 どちらも「部分問題の答えを表に持ち、次の答えをそこから作る」ことで、素朴には爆発する計算を多項式に落としている。違いは、前向きが確率の和を取るのに対し、編集距離は回数の最小値を取る点だけである。

    この授業で扱う統計数理の範囲外

    操作ごとに重みを変える（置換は2、挿入は1など）重み付き編集距離や、最適な対応づけを復元するバックトレースの実装は扱わない。ここで必要なのは、WER の分子が「最小の操作回数」として一意に決まることである。

    使った数学：場合分けと、最小値についての漸化式。

    スライド7: CER（Character Error Rate）¶

    CERの定義¶

    文字レベルの誤り率。日本語評価の標準指標。

    \[\text{CER} = \frac{S_c + D_c + I_c}{N_c} \times 100\%\]
    • \(S_c, D_c, I_c\): 文字レベルの置換・削除・挿入数
    • \(N_c\): 正解文の総文字数

    日本語でのCER計算例¶

    例題（CBTに出題）:

    正解文: 今日は天気がいい
    認識結果: 今日はてんきがいい

    文字単位のアライメント:

    正解:   今 日 は 天 気 が い い
認識:   今 日 は て ん き が い い

差分を動的計画法で計算:
  今 → 今 (一致)
  日 → 日 (一致)
  は → は (一致)
  天 → て (置換: S+1)
  気 → ん (置換: S+1)
     → き (挿入: I+1)
  が → が (一致)
  い → い (一致)
  い → い (一致)
    \[S_c=2, \quad D_c=0, \quad I_c=1, \quad N_c=8\]
    \[\text{CER} = \frac{2+0+1}{8} = \frac{3}{8} = 37.5\%\]

    別の解釈: 認識結果「てんき」（3文字）と正解「天気」（2文字）の編集距離は3（天→て、気→ん、+きの挿入）なので、その部分だけで \(3/8 = 37.5\%\)。

    WERとCERの使い分け¶

    指標 対象言語 使う理由
    WER 英語・スペース分かち書きの言語 単語がスペースで明確に区切られる
    CER 日本語・中国語・アラビア語 単語分かち書きが難しく、文字単位が妥当

    日本語の問題: 「今日は良い天気だ」を単語に分けると「今日/は/良い/天気/だ」など形態素解析が必要。文字単位ならその問題がない。

    スライド8: SLUEベンチマークとは¶

    SLUE（Spoken Language Understanding Evaluation）¶

    Shon et al. (2022, MIT) が提案した、音声言語理解（SLU） の評価ベンチマーク。

    単純な「テキスト起こし精度（WER）」を超えて、意味理解の精度を評価する。

    SLUEの2タスク¶

    タスク1: 固有表現認識（NER: Named Entity Recognition） - 音声から人名・地名・組織名などの固有表現を抽出する - 評価指標: \(F_1\)スコア（適合率と再現率の調和平均）

    入力音声: "田中太郎さんが東京大学で発表した"
出力: 
  田中太郎 → PER（人名）
  東京大学 → ORG（組織名）

    タスク2: 感情分析（Sentiment Analysis） - 音声の感情的な極性（ポジティブ・ネガティブ・ニュートラル）を分類する - 評価指標: 加重\(F_1\)スコア

    SLUEの意義¶

    評価の種類 測れること 測れないこと
    WER/CER 文字・単語の正確さ 意味の理解、下流タスク性能
    SLUE-NER 固有表現の抽出精度 WERが高くても意味は取れることがある
    SLUE-SA 感情の把握精度 書き起こし精度と感情認識精度は相関しない場合も

    例: 「すごい！」と「すごい？」は文字列が同じでも感情が異なる。音響的な情報が重要。

    現在のベンチマーク状況¶

    自己教師あり学習モデル（wav2vec 2.0、HuBERT、WavLM等）は、少量の下流ラベルで SLUEで高い性能を示し、従来のパイプライン（ASR→テキスト解析）に匹敵または超える結果が得られている。

    スライド9: 混同行列による分析¶

    音素レベルの混同行列¶

    どの音素が他のどの音素に誤認識されやすいかを可視化する。

    音素混同行列の例（行=正解音素、列=認識音素）:

         /a/  /i/  /u/  /e/  /o/  ...
正解/a/ [  95   2    1    1    1  ...]
正解/i/ [   3  90    3    2    2  ...]
正解/u/ [   2   4   88    2    4  ...]
...
（値は各音素が認識された割合 %）

対角成分が高いほど良い認識

    混同行列から読み取れる情報¶

    1. 系統的誤り: 特定の音素が常に同じ音素に誤られる
      例: /ɯ/（日本語の「ウ」）が /u/ と混同されるなど
    2. 音響的近さ: 混同されやすい音素は音響的に似ている傾向がある
    3. 改善方向: 特定の音素ペアの学習データを増やす、特徴量設計を見直すなど

    橋（はし） 箸（はし） 同音異義語。LMで解決できることも
    音楽 音学 漢字変換の問題

    スライド10: エラー分析の方法論¶

    体系的なエラー分析のステップ¶

    Step 1: 量的分析 - WER/CERの全体値を計算 - 条件別（騒音レベル、話者、発話速度）に分類

    Step 2: エラーの分類

    エラー種別 説明 対処法
    音響的誤り 類似音の混同（/s/→/z/等） 音響モデルの改善、データ増強
    語彙外単語（OOV） 辞書に存在しない単語 辞書拡張、文字モデル使用
    言語モデルエラー 音響的には正しいが文脈と合わない LM更新、ドメイン適応
    ハルシネーション 入力に無いテキストを出力 Whisperなど大規模モデルで発生

    Step 3: 対話型デバッグ - 誤りの多いファイルを個別に聴取・分析 - アテンションウェイトの可視化（Whisperのdecoder attention等） - 音響モデルの確率分布確認

    Step 4: 改善策の立案と評価 - データ増強、ファインチューニング等の施策を実施 - 改善前後でWER/CERを比較

    方法2：WER/CERを自前で実装（アルゴリズム理解のため）¶

    import numpy as np

def edit_distance(reference: list, hypothesis: list) -> tuple[int, int, int, int]:
    """
    動的計画法で編集距離を計算し、S/D/Iの内訳も返す。

    Args:
        reference: 正解の単語リスト（または文字リスト）
        hypothesis: 認識結果の単語リスト（または文字リスト）

    Returns:
        (S, D, I, total_distance): 置換数、削除数、挿入数、総編集距離
    """
    m = len(reference)
    n = len(hypothesis)

    # DP テーブル（コスト）
    dp = np.zeros((m + 1, n + 1), dtype=int)

    # 初期条件
    for i in range(m + 1):
        dp[i][0] = i
    for j in range(n + 1):
        dp[0][j] = j

    # DP の填充
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if reference[i - 1] == hypothesis[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]  # 一致
            else:
                dp[i][j] = min(
                    dp[i - 1][j] + 1,      # 削除
                    dp[i][j - 1] + 1,      # 挿入
                    dp[i - 1][j - 1] + 1   # 置換
                )

    # バックトレースでS/D/Iを数える
    i, j = m, n
    S, D, I = 0, 0, 0
    while i > 0 or j > 0:
        if i > 0 and j > 0 and reference[i - 1] == hypothesis[j - 1]:
            i -= 1
            j -= 1
        elif i > 0 and j > 0 and dp[i][j] == dp[i - 1][j - 1] + 1:
            S += 1  # 置換
            i -= 1
            j -= 1
        elif i > 0 and dp[i][j] == dp[i - 1][j] + 1:
            D += 1  # 削除
            i -= 1
        else:
            I += 1  # 挿入
            j -= 1

    return S, D, I, dp[m][n]

def compute_wer(reference_text: str, hypothesis_text: str) -> float:
    """単語レベルのWERを計算する"""
    ref_words = reference_text.split()
    hyp_words = hypothesis_text.split()
    S, D, I, _ = edit_distance(ref_words, hyp_words)
    N = len(ref_words)
    if N == 0:
        return 0.0
    wer_score = (S + D + I) / N
    print(f"  正解単語数 N={N}, S={S}, D={D}, I={I}")
    return wer_score

def compute_cer(reference_text: str, hypothesis_text: str) -> float:
    """文字レベルのCERを計算する（日本語対応）"""
    ref_chars = list(reference_text.replace(" ", ""))
    hyp_chars = list(hypothesis_text.replace(" ", ""))
    S, D, I, _ = edit_distance(ref_chars, hyp_chars)
    N = len(ref_chars)
    if N == 0:
        return 0.0
    cer_score = (S + D + I) / N
    print(f"  正解文字数 N={N}, S={S}, D={D}, I={I}")
    return cer_score

    複数ファイルの一括評価¶

    import os
from jiwer import cer as jiwer_cer

def evaluate_asr_system(audio_dir: str, reference_dir: str, model) -> dict:
    """
    音声ファイルのディレクトリに対してASRシステムを評価する。

    Args:
        audio_dir: 音声ファイルが格納されたディレクトリ
        reference_dir: 正解テキストファイルが格納されたディレクトリ
        model: Whisperモデルオブジェクト

    Returns:
        評価結果の辞書
    """
    total_s = total_d = total_i = total_n = 0
    results = []

    for audio_file in sorted(os.listdir(audio_dir)):
        if not audio_file.endswith(".wav"):
            continue

        base = os.path.splitext(audio_file)[0]
        ref_file = os.path.join(reference_dir, base + ".txt")

        if not os.path.exists(ref_file):
            continue

        with open(ref_file, "r", encoding="utf-8") as f:
            reference = f.read().strip()

        audio_path = os.path.join(audio_dir, audio_file)
        result = model.transcribe(audio_path, language="ja")
        hypothesis = result["text"].strip()

        # 文字レベルの編集距離
        ref_chars = list(reference)
        hyp_chars = list(hypothesis)
        S, D, I, _ = edit_distance(ref_chars, hyp_chars)
        N = len(ref_chars)

        total_s += S
        total_d += D
        total_i += I
        total_n += N

        results.append({
            "file": audio_file,
            "reference": reference,
            "hypothesis": hypothesis,
            "cer": (S + D + I) / N if N > 0 else 0.0
        })

    overall_cer = (total_s + total_d + total_i) / total_n if total_n > 0 else 0.0

    return {
        "overall_cer": overall_cer,
        "total_S": total_s,
        "total_D": total_d,
        "total_I": total_i,
        "total_N": total_n,
        "per_file": results
    }

    正解文: 私 は 毎日 学校 へ 行く（6単語）

「へ」が削除されている: D=1
S=0, I=0
N=6（正解の総単語数）

    正解文: 今日は天気がいい（8文字）
    認識結果: 今日はてんきがいい（9文字）

    このときのCERはいくらか。

    1. 1/8 = 12.5%
    2. 2/8 = 25.0%
    3. 3/8 = 37.5%
    4. 4/8 = 50.0%

操作:
「天」→「て」: 置換 (S+1)
「気」→「ん」: 置換 (S+1)

    正解は選択肢3。

    問3: WERとCERの使い分け¶

    WERよりもCERを使うことが適切な場合として最も正しいものはどれか。

    1. 英語の認識結果を評価するとき
    2. 日本語の認識結果を評価するとき（単語分かち書きが難しいため）
    3. 認識結果に挿入エラーが多いとき
    4. 言語モデルを使わないEnd-to-Endシステムを評価するとき

    正解: 2

    解説:
    - 選択肢1は誤り。英語はスペースで単語が区切られるため、WERが標準的に使われる。
    - 選択肢2が正しい。日本語・中国語・アラビア語などは単語境界が明確でない（形態素解析が必要）。CERは文字単位で計算するためこの問題を回避できる。日本語ASRの評価ではCERが標準指標。
    - 選択肢3は誤り。挿入エラーの多さはCERに切り替える理由にはならない。WERでも挿入は計上される。

    問4: 編集距離の理解¶

    reference = [A, B, C, D]（4単語）、hypothesis = [A, C, D, E]（4単語）のとき、最小編集距離（単語レベル）はいくらか。

    1. 1
    2. 2
    3. 3
    4. 4

    正解: 2

    解説:

    動的計画法で編集距離を計算するか、直感的に考える。

    参照: A  B  C  D
仮説: A     C  D  E

最短変換:
  B を削除 (D+1)
  E を挿入 (I+1)

合計: D=1, I=1, S=0 → 編集距離 = 2

    別の対応も考えられるが（例: B→E で置換S=1 + Cのシフト問題）、最小は2。

    \[\text{WER} = \frac{0+1+1}{4} = \frac{2}{4} = 50\%\]

    3. 日本語特有の評価指標であり、漢字変換精度を評価する

    解説:
    - 選択肢1は誤り。WERとCERは文字・単語レベルの評価。SLUEはその先の意味理解の評価。
    - 選択肢2が正しい。SLUE（Spoken Language Understanding Evaluation）はMITが提案した意味理解の評価ベンチマーク。固有表現認識（NER, \(F_1\)スコアで評価）と感情分析（ポジ・ネガ・ニュートラル分類）の2タスクを含む。WERが低くても意味理解が正確とは限らないという問題意識から生まれた。
    - 選択肢3は誤り。SLUEは英語を対象としたベンチマークとして開始された。漢字変換精度を測るものではない。
    - 選択肢4は誤り。SLUEはEnd-to-End音声理解システム全般を対象とし、特定のモデル（LLM）を前提としない。

    まとめ¶

    本日の学習内容¶

    1. 音声認識システム全体構成: AM（音響モデル）＋LM（言語モデル）＋デコーダ（ビーム探索）
    2. WER: \(\frac{S+D+I}{N}\)。単語レベルの誤り率。英語の標準指標。
    3. CER: \(\frac{S_c+D_c+I_c}{N_c}\)。文字レベルの誤り率。日本語の標準指標。
    4. 編集距離: WER/CERの計算基盤。動的計画法で \(O(MN)\) で求まる。
    5. SLUEベンチマーク: NER・感情分析による意味理解の評価。WER/CERを超えた評価。
    6. エラー分析: 混同行列・エラー種別分類・改善策立案の方法論。

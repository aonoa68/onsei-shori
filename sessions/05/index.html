    本回の到達目標¶

    1. メル尺度が人間の聴覚特性を反映する理由を説明できる
    2. MFCCの計算ステップ（前処理→メルフィルタ→対数→DCT）を順に説明できる
    3. Pythonで MFCC を計算・可視化できる
    4. デルタ特徴量の意味を説明できる

    進化の視点：メル尺度は、聴覚の進化的な設計を写し取っている¶

    メル尺度は、低い周波数ほど細かく、高い周波数ほど粗く分解する。これは数学的な都合ではなく、蝸牛の分解能がそうなっていることの近似である。

    低域に分解能を割く配置は、音声のフォルマントや基本周波数がその帯域にあること、そして雑音の中で音源を分離するのに有利なことと整合する。

    技術への接続：MFCC が長く使われてきたのは、ヒトが音声を聞き分けるときに使っている情報を、少ない次元で残すからである。逆にいえば、ヒトが捨てている情報も一緒に捨てている。近年のモデルが対数メルスペクトログラムや生の波形を直接扱うのは、その「捨てすぎ」を避ける方向でもある（第7回・第8回）。

    問い：ヒトの耳に合わせた特徴量は、機械にとっても最適か。

    スライド1: なぜ「メル尺度」が必要か—人間の聴覚の非線形性¶

    人間の耳はすごくいい加減（でも賢い）

    私たちの耳は、すべての周波数を等しく聴いているわけではありません。

    実験的事実：

    物理的差 知覚される差
    100Hz → 200Hz（100Hzの差） とても大きな差
    5000Hz → 5100Hz（100Hzの差） ほとんど聞き取れない

    低音域では小さな差を敏感に感じ取り、高音域では大きな差でも鈍感。
    これが「対数的な知覚」です。

    音楽で体感してみよう

    ピアノの鍵盤では、1オクターブ上がると周波数は2倍になります： - ラ（A4）：440 Hz → ラ（A5）：880 Hz - ラ（A5）：880 Hz → ラ（A6）：1760 Hz

    どの「1オクターブ」も同じ音程差に聞こえるのに、Hz での差は全然違います。

    スライド2: メル変換の数式とグラフ¶

    メル尺度（Mel scale）の定義

    \[ m = 2595 \log_{10}\left(1 + \frac{f}{700}\right) \]

    逆変換（メル → Hz）：

    \[ f = 700\left(10^{m/2595} - 1\right) \]

    直感的理解

    • \(f = 0\) Hz → \(m = 0\) メル
    • \(f = 700\) Hz → \(m \approx 781\) メル（700 は式の中の定数で、線形から対数へ移る目安）
    • \(f = 1000\) Hz → \(m \approx 1000\) メル（Hz とメルの目盛りが一致する点）
    • \(f = 7000\) Hz → \(m \approx 2702\) メル

    700 Hz 以下では「ほぼ線形」、700 Hz 以上では「対数的に圧縮」。

    Pythonでメル変換を可視化

    導出①：低域では線形、高域では対数 ―― 1つの式が両方をやっている

    スライド1の表をもう一度見る。100 Hz → 200 Hz は「とても大きな差」、5,000 Hz → 5,100 Hz は「ほとんど聞き取れない」。Hz で測ればどちらも同じ 100 Hz である。これをメル尺度で測り直す。

    \[ m(200) - m(100) = 132.74 \ \text{メル}, \qquad m(5100) - m(5000) = 19.60 \ \text{メル} \]

    同じ 100 Hz が、メルでは約 6.8 倍ちがう。 表が言葉で述べていたことが、この尺度では数値になる。なぜそうなるのかを、式の両端から見る。

    高いほうの端：\( f \) が 700 に比べて十分大きいとき、\( 1 + f/700 \approx f/700 \) なので

    \[ m \;\approx\; 2595 \log_{10}\frac{f}{700} \]

    対数の中身が \( f \) に比例しているので、周波数を2倍にすると一定量だけ増える形になる。その一定量は \( 2595\log_{10} 2 = 781.17 \) メルである。スライド1の「どの1オクターブも同じ音程差に聞こえる」は、この性質にあたる。

    ただし音声で扱う帯域では、落とした 1 がまだ効いている。実際に計算すると 1,000→2,000 Hz で 521.37 メル、2,000→4,000 Hz で 624.70 メル、4,000→8,000 Hz で 693.96 メルと、781.17 に少しずつ近づいていく。完全に等間隔になるのはもっと高い周波数での話である。

    低いほうの端：\( x \) が小さいとき \( \log_{10}(1+x) \approx x / \ln 10 \) なので

    \[ m \;\approx\; \frac{2595}{700 \ln 10} f \;=\; 1.6100\, f \]

    \( f \) に比例する、つまり線形になる。既存の説明にある「700 Hz 以下ではほぼ線形」はこのことである。ただし「ほぼ」の中身は見ておきたい。

    \( f \) 厳密な \( m \) 線形近似 \( 1.61 f \) ずれ
    50 Hz 77.75 80.50 +3.5%
    100 Hz 150.49 161.00 +7.0%
    200 Hz 283.23 322.00 +13.7%

    200 Hz ですでに 1 割以上ずれる。線形なのは「厳密に」ではなく「対数域に比べれば」という意味である。

    分母の 700 は、この2つの振る舞いが入れ替わる折れ目にあたる。低域ではフィルタが密に、高域では粗に並ぶ、というメルフィルタバンクの配置は、すべてこの1つの式から出ている。

    2595 と 700 はどこから来たか

    この2つの定数は、理論から導かれたものではない。音の高さの知覚を答えてもらう実験の結果に、この形の式を当てはめて決めた値である。だから文献によって 2595 が 1127（自然対数を使う版）になったり、700 が別の値になったりする。導出できるのは「なぜこの形だと低域で線形・高域で対数になるか」までで、定数の値そのものは実験が決めている。この当てはめの議論は、この授業で扱う数理の範囲外である。

    使った数学：対数の性質 \( \log(ab)=\log a + \log b \)、\( \log_{10}(1+x)\approx x/\ln 10 \) という1次近似（数III）。

    スライド3: メルフィルタバンク—三角フィルタの配置¶

    メルフィルタバンクとは

    スペクトログラムの周波数軸を、メル尺度で等間隔に並んだ三角形フィルタ群でまとめる処理です。

    三角フィルタの特徴

    • 低周波：フィルタが狭い（細かく分析）
    • 高周波：フィルタが広い（まとめて分析）
    • 人間の聴覚と同じ分解能になる

    フィルタバンクの処理手順

    FFTスペクトル（例：1025ビン）
  ↓
三角フィルタをかける（例：40個）
  ↓
各フィルタの出力（各三角フィルタ内のエネルギーの合計）
  ↓
40次元のメルエネルギーベクトル

    数式で表すと

    \(k\)番目のフィルタの出力：

    \[ S[k] = \sum_{n} X[n] \cdot H_k[n] \]
    • \(X[n]\)：パワースペクトル（\(|D[n]|^2\)）
    • \(H_k[n]\)：\(k\)番目の三角フィルタ

    スライド4: メルフィルタバンクをPythonで実装¶

    # ===== セル2：自前でメルフィルタバンクを計算する =====

import numpy as np
import matplotlib.pyplot as plt

def hz_to_mel(f):
    """Hz → Mel 変換"""
    return 2595 * np.log10(1 + f / 700)

def mel_to_hz(m):
    """Mel → Hz 変換"""
    return 700 * (10 ** (m / 2595) - 1)

def make_mel_filterbank(n_filters=26, n_fft=512, sr=22050, f_min=0, f_max=None):
    """
    メルフィルタバンクを生成する
    Parameters:
        n_filters: フィルタ数
        n_fft: FFT長
        sr: サンプリングレート
        f_min, f_max: 分析する周波数範囲
    Returns:
        filterbank: shape (n_filters, n_fft//2 + 1)
    """
    if f_max is None:
        f_max = sr / 2

    n_freqs = n_fft // 2 + 1
    freqs = np.linspace(0, sr / 2, n_freqs)  # FFTの周波数軸

    # メル尺度でのフィルタ中心点（n_filters + 2個：両端含む）
    mel_min = hz_to_mel(f_min)
    mel_max = hz_to_mel(f_max)
    mel_centers = np.linspace(mel_min, mel_max, n_filters + 2)
    hz_centers  = mel_to_hz(mel_centers)  # 対応するHzの位置

    filterbank = np.zeros((n_filters, n_freqs))
    for k in range(n_filters):
        f_left   = hz_centers[k]
        f_center = hz_centers[k + 1]
        f_right  = hz_centers[k + 2]
        # 三角フィルタの計算
        for i, f in enumerate(freqs):
            if f_left <= f <= f_center:
                filterbank[k, i] = (f - f_left) / (f_center - f_left)
            elif f_center < f <= f_right:
                filterbank[k, i] = (f_right - f) / (f_right - f_center)
    return filterbank, freqs, hz_centers

# フィルタバンクを生成・可視化
fb, freqs, centers = make_mel_filterbank(n_filters=26, n_fft=512, sr=22050)

plt.figure(figsize=(12, 5))
for k in range(fb.shape[0]):
    plt.plot(freqs, fb[k], alpha=0.7)
plt.xlabel("周波数 (Hz)", fontsize=12)
plt.ylabel("フィルタの重み", fontsize=12)
plt.title("メルフィルタバンク（26フィルタ、0〜11025Hz）", fontsize=13)
plt.xlim(0, 11025)
plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.show()

print(f"フィルタバンクの形状: {fb.shape}")
print(f"フィルタ中心周波数 (Hz): {centers[1:-1].round(0)}")

    スライド5: ログメルスペクトログラム¶

    なぜ「対数」を取るか

    1. 人間の聴覚はエネルギーに対して対数的（ウェーバー-フェヒナーの法則）
    2. 静かな音と大きな音の範囲が非常に広い（dBスケールが必要）
    3. 機械学習モデルが扱いやすい数値範囲になる

    計算式

    \[ \text{LogMel}[k] = \log\left(S[k] + \epsilon\right) \]
    • \(S[k]\)：\(k\)番目のメルフィルタバンクの出力（エネルギー）
    • \(\epsilon\)：ゼロ除算防止の小さな値（例：\(10^{-9}\)）

    Pythonでログメルスペクトログラムを描く

    # ===== セル3：ログメルスペクトログラムの描画 =====

import librosa
import librosa.display
import numpy as np
import matplotlib.pyplot as plt
from IPython.display import Audio, display

# 音声の読み込み

y, sr = librosa.load(audio_path, sr=22050)
display(Audio(y, rate=sr))

# メルスペクトログラムを計算

fig, axes = plt.subplots(2, 1, figsize=(12, 8))

# 通常スペクトログラム（比較用）

fig.colorbar(img2, ax=axes[1], format='%+.0f dB')

    スライド6: DCT（離散コサイン変換）の役割¶

    DCTとは

    離散コサイン変換（DCT）は、信号をコサイン関数の重ね合わせで表す変換です。

    \[ C[n] = \sum_{k=0}^{K-1} \log S[k] \cdot \cos\left(\frac{\pi n (k + 0.5)}{K}\right) \]
    • \(K\)：メルフィルタの数
    • \(n\)：ケプストラム次数
    • \(C[n]\)：\(n\)番目のMFCC係数

    メルフィルタバンク出力にDCTをかける目的

    1. 圧縮：40〜128次元のログメルエネルギーを 13〜40次元に削減
    2. 非相関化：隣接するメルフィルタバンクの出力は相関が高い → DCTで独立した成分に分離
    3. エネルギー分離：C[0]は全体的なエネルギー、高次は細かいスペクトル形状

    ケプストラム（Cepstrum）

    「スペクトルのスペクトル」という概念。

    \[ \text{ケプストラム} = \text{IFFT}\left(\log |\text{FFT}(x)|^2\right) \]
    • ピッチ（声帯振動）とフォルマント（声道形状）を分離できる
    • MFCCはメルフィルタバンク版のケプストラム

    なぜ低次のDCT係数だけを使うか

    DCT係数次数 表すもの
    C[0] 全体エネルギー（通常除外）
    C[1]〜C[4] 大まかなスペクトル形状（フォルマント）
    C[5]〜C[12] 細かいスペクトル形状
    C[13]以上 ノイズ的、音声認識にはほぼ不要
    導出②：なぜ「対数をとってから」変換するのか（核心）

    音声は、声帯の振動 \( e[n] \) が声道という管を通って出てくる。管を通る操作は畳み込みで書ける。

    \[ x[n] \;=\; e[n] * h[n] \]

    ここで \( h[n] \) は声道の特性である。畳み込みは、周波数の側で見ると掛け算になる。

    \[ |X[k]| \;=\; |E[k]| \cdot |H[k]| \]

    知りたいのは、ふつう \( |H[k]| \) のほうである。母音を決めているのはフォルマント、つまり声道の形だからである。ところが観測できるのは積のほうで、掛け算のままでは2つを引き離せない。

    ここで対数をとる。

    \[ \log|X[k]| \;=\; \log|E[k]| \;+\; \log|H[k]| \]

    掛け算が足し算になった。 これが対数の役割である。スライド5では「聴覚が対数的だから」「数値範囲が扱いやすいから」と説明したが、MFCC にとってはこちらの理由のほうが本質的である。

    足し算にさえなれば、あとは2つの成分の性質の違いで分けられる。周波数軸に沿って見ると、

    • \( \log|E[k]| \) は、基本周波数の間隔で細かく上下する（男性の声なら 100 Hz 程度の周期で振動する）
    • \( \log|H[k]| \) は、フォルマントの山をつくるゆるやかなうねりである

    細かい振動とゆるやかな変化が足し合わさっている。ならば、周波数軸をもう一度「波の分解」にかければ、細かいほうは高次に、ゆるやかなほうは低次に分かれる。既存の式

    \[ \text{ケプストラム} = \text{IFFT}\left(\log |\text{FFT}(x)|^2\right) \]

    はこれをそのまま書いたものである。MFCC は、この最後の変換を DCT に置き換え、周波数軸をメル尺度にしたものにあたる。

    ケプストラムという名前

    spectrum（スペクトル）の前半を綴りごとひっくり返して cepstrum。周波数軸をさらに変換した先なので、ふつうのスペクトルと取り違えないように作られた語である。横軸の単位も frequency をひっくり返して quefrency と呼ぶ。名前の遊びに見えるが、「もう一段、外側にいる」ことを忘れないための工夫である。

    畳み込みが周波数で積になること（畳み込み定理）の証明と、位相まで含めた複素ケプストラムの扱いは、この授業で扱う数理の範囲外である。

    使った数学：対数の性質 \( \log(ab)=\log a+\log b \)（数II）。畳み込みが積になるという事実（結果のみ使用）。

    導出③：DCT は何をしているのか ―― なぜ13次で足りるのか

    上の式をもう一度見る。

    \[ C[n] \;=\; \sum_{k=0}^{K-1} \log S[k] \cdot \cos\left(\frac{\pi n (k + 0.5)}{K}\right) \]

    第4回の導出①と同じ形である。あちらは時間の列 \( x[n] \) と波との内積だった。こちらはメル軸に沿って並んだ値の列 \( \log S[k] \) と、余弦波との内積である。変換する軸が時間から周波数に変わっただけで、やっていることは変わらない。

    まず \( n = 0 \) を入れてみる。\( \cos 0 = 1 \) なので

    \[ C[0] \;=\; \sum_{k=0}^{K-1} \log S[k] \]

    全フィルタの対数エネルギーをただ足したものになる。声の大きさがそのまま乗る量なので、表にあるとおり通常は捨てる。マイクとの距離が変わっただけで動いてしまい、母音の区別には使えないからである。

    次に、なぜ低次だけで足りるのか。メルフィルタバンクは三角フィルタを重ねて並べるので、隣り合うフィルタは同じ周波数成分を共有している。つまり \( \log S[k] \) の隣どうしは強く相関している。

    相関しているということは、同じ情報を何度も持っているということである。余弦波は互いに直交しているので、これで分解し直すと、重複していた情報が整理され、少数の低次係数に集まる。導出②で見たとおり、知りたいフォルマントの情報はもともとゆるやかなうねりとして入っている。ゆるやかなうねりは低次の余弦波で表せる。

    だから表にあるとおり、\( C[1] \) から \( C[12] \) あたりまででフォルマントの形は足りる。それより上は主に \( \log|E[k]| \) 側の細かい振動、つまり声の高さと雑音であって、母音や子音を区別するのには使わない。13次元という定番の数字は、この切り分けから来ている。

    DCT が「相関を落とす変換として最も良い」といえるのは、対象の相関がある特定の形をしているときに限られる。主成分分析との関係を厳密に述べるにはその条件を確かめる必要があり、この授業で扱う数理の範囲外である。

    使った数学：余弦の値 \( \cos 0 = 1 \)、ベクトルの内積と直交（線形代数I）、第4回の導出①。

    スライド7: MFCCの計算ステップ全体¶

    MFCC計算のフローチャート

    入力：音声波形 x[n]
  │
  ▼
① プリエンファシス（高域強調）
   x'[n] = x[n] - α · x[n-1]   (α ≈ 0.97)
  │
  ▼
② フレーム分割 + 窓掛け（ハニング窓）
   各フレーム：25ms、オーバーラップ：10ms
  │
  ▼
③ FFT → パワースペクトル
   |X[k]|²
  │
  ▼
④ メルフィルタバンクを適用
   S[m] = Σ H_m[k] · |X[k]|²
  │
  ▼
⑤ 対数を取る
   log S[m]
  │
  ▼
⑥ DCTを適用
   C[n] = Σ log S[m] · cos(π·n·(m+0.5)/M)
  │
  ▼
出力：MFCC（例：13次元ベクトル）
各フレームに1つ → 全体で (13 × フレーム数) の行列

    スライド8: MFCC のPython実装（librosa 使用）¶

    # ===== セル4：librosa で MFCC を計算・可視化 =====

import librosa
import librosa.display
import numpy as np
import matplotlib.pyplot as plt
from IPython.display import Audio, display

# 音声読み込み
audio_path = librosa.example('trumpet')

mfcc = librosa.feature.mfcc(y=y, sr=sr,

                               n_mels=40,
                               fmin=0,
                               fmax=sr/2)

print(f"  各フレームの時間幅: {512/sr*1000:.1f} ms")

# 平均・標準偏差（音声認識でよく使う統計量）
print(f"\n各次元の平均値: {mfcc.mean(axis=1).round(2)}")
print(f"各次元の標準偏差: {mfcc.std(axis=1).round(2)}")

    スライド9: デルタ・デルタデルタ特徴量¶

    静的特徴量だけでは不十分

    MFCC は「ある瞬間のスペクトル形状」を表しますが、音声は時間的に変化します。

    「あ → い」の変化中に何が起きているか → 微分で捉える

    デルタ（Δ）特徴量：1次微分

    \[ \Delta C_t[n] = \frac{\sum_{k=1}^{K} k \left(C_{t+k}[n] - C_{t-k}[n]\right)}{2 \sum_{k=1}^{K} k^2} \]

    通常 \(K = 2\)（前後2フレームを使用）

    • MFCC単体：スペクトルの形（母音の種類など）
    • ΔMFCC：スペクトルの変化（音素間の遷移）
    • ΔΔMFCC：変化の変化（加速度的な変化）

    一般的な次元数の組み合わせ

    構成 次元数 用途
    MFCC 13 最小構成
    MFCC + Δ 26 標準的
    MFCC + Δ + ΔΔ 39 音声認識の定番
    MFCCを増やす 20, 40 深層学習向け 
    # ===== セル5：デルタ・デルタデルタ特徴量の計算と可視化 =====

import librosa
import librosa.display
import numpy as np
import matplotlib.pyplot as plt

# 音声読み込み
audio_path = librosa.example('trumpet')
y, sr = librosa.load(audio_path, sr=22050)

# MFCC（13次元）
mfcc    = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=13,
                                 n_fft=2048, hop_length=512, n_mels=40)
# デルタ
mfcc_d  = librosa.feature.delta(mfcc, width=5)   # 1次差分
# デルタデルタ
mfcc_dd = librosa.feature.delta(mfcc, width=5, order=2)  # 2次差分

# 連結（39次元）
mfcc_full = np.concatenate([mfcc, mfcc_d, mfcc_dd], axis=0)
print(f"連結後の特徴量の形状: {mfcc_full.shape}（39次元 × フレーム数）")

# 可視化
fig, axes = plt.subplots(3, 1, figsize=(12, 10))

for ax, feat, title in zip(axes,
                            [mfcc, mfcc_d, mfcc_dd],
                            ["MFCC（13次元）",
                             "ΔMFCCs（1次差分）",
                             "ΔΔMFCCs（2次差分）"]):
    img = librosa.display.specshow(feat, sr=sr, hop_length=512,
                                    x_axis='time', ax=ax, cmap='coolwarm')
    ax.set_title(title)
    ax.set_ylabel("次数")
    fig.colorbar(img, ax=ax)

plt.suptitle("MFCC + Δ + ΔΔ（39次元特徴量）", fontsize=13, y=1.01)
plt.tight_layout()
plt.show()

    テスト問題（全5問、各1点、Google Formsで回答）¶

    問1¶

    メル尺度（Mel scale）について正しい説明はどれか。

    A. 全周波数帯域を等間隔の線形スケールで表したもの
    B. 人間の聴覚の非線形性に基づき、低音域を圧縮し高音域を拡張したもの
    C. 人間の聴覚特性を反映し、低音域を細かく、高音域を粗く扱うもの
    D. 音声の基本周波数（F0）を自動検出するための尺度

    正解：C

    解説：
    メル尺度は人間の聴覚特性を反映した非線形スケールです。人間の耳は低周波数帯域の差（例：100Hz vs 200Hz）を敏感に感じる一方、高周波数帯域の差（例：5000Hz vs 5100Hz）は鈍感です。この特性に合わせ、メル尺度では低音域を細かく（多くのフィルタを配置）、高音域を粗く（少ないフィルタで広い帯域を担当）設計します。

    Bは「高音域を拡張」が逆の説明です（実際は高音域が圧縮・粗く扱われます）。Aは線形スケールなのでメル尺度の特徴に反します。Dはピッチ検出の話であり、メル尺度の目的ではありません。

    問2¶

    MFCCの計算ステップとして、正しい順番はどれか。

    A. FFT → メルフィルタバンク → 対数 → DCT
    B. DCT → FFT → メルフィルタバンク → 対数
    C. メルフィルタバンク → FFT → 対数 → DCT
    D. FFT → 対数 → メルフィルタバンク → DCT

    正解：A

    解説：
    MFCCの計算順序は以下の通りです：

    1. FFT（高速フーリエ変換）：時間領域の信号を周波数領域に変換する
    2. メルフィルタバンク：FFTで得た周波数スペクトルにメルフィルタを適用し、人間の聴覚特性に合わせた40〜128次元のエネルギーを得る
    3. 対数（log）：人間の音の大きさの知覚が対数的なため、対数を取る
    4. DCT（離散コサイン変換）：相関を除去し、コンパクトな特徴量に圧縮する

    この順序の覚え方：「フ（FFT）メ（メルフィルタ）対（対数）D（DCT）」

    問3¶

    librosaで13次元のMFCCを計算するコードとして正しいものはどれか。

    A. mfcc = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=13)
    B. mfcc = librosa.stft(y, n_fft=13)
    C. mfcc = librosa.feature.melspectrogram(y=y, sr=sr, n_mels=13)
    D. mfcc = librosa.feature.mfcc(y=y, sr=sr, n_fft=13)

    正解：A

    解説：
    librosa.feature.mfcc() がMFCCを計算する関数で、n_mfcc パラメータで次元数（MFCC係数の数）を指定します。

    • B：librosa.stft() はSTFTを計算する関数（MFCCではない）
    • C：librosa.feature.melspectrogram() はメルスペクトログラムを返す（MFCCではない）
    • D：n_fft=13 はFFTの長さを13にすることを意味し、MFCCの次元数ではない（かつ13というFFT長は実用上使わない）

    問4¶

    デルタ（Δ）MFCC特徴量について正しい説明はどれか。

    A. MFCCの次元数を増やして、より多くの周波数帯域を分析したもの
    B. MFCC係数の時間的な変化（1次差分）を表す特徴量
    C. DCT係数をさらにDCTにかけた2段階変換の結果
    D. ノイズ除去のためにMFCCを平滑化したもの

    正解：B

    解説：
    デルタ（Δ）MFCCは、MFCCの時間方向の1次差分（微分）です。前後数フレームのMFCCの差を使って計算します：

    \[\Delta C_t = \frac{\sum_{k=1}^{K} k (C_{t+k} - C_{t-k})}{2\sum_{k=1}^{K}k^2}\]

    静的なMFCC（13次元）だけでは「今この瞬間の音のスペクトル形状」しかわかりませんが、ΔMFCC（13次元）を加えることで「スペクトルがどのように変化しているか」という動的な情報が加わります。音声認識ではMFCC(13) + ΔMFCC(13) + ΔΔMFCC(13) = 39次元が定番です。

    問5¶

    MFCCと比較してログメルスペクトログラムを音声認識に使う利点として適切なものはどれか。

    A. DCTによる次元削減により、MFCCより情報量が少なくなる
    B. DCTを行わないため、スペクトル全体のより詳細な情報が保持される
    C. メルフィルタバンクを使わないため、線形の周波数分解能が保たれる
    D. ログメルスペクトログラムはリアルタイム計算が不可能なため、バッチ処理専用

    正解：B

    解説：
    ログメルスペクトログラムはMFCCと異なり、DCTによる次元圧縮を行いません。

    • MFCC：メルフィルタバンク出力（例：40次元）→ DCT → 低次の係数のみ（例：13次元）を使用
    • ログメルスペクトログラム：メルフィルタバンク出力（例：128次元）をそのまま使用

    DCTで高次成分を捨てることで情報が失われる可能性がある一方、ログメルスペクトログラムは全フィルタバンクのエネルギー情報を保持します。深層学習（CNN、Transformer）はこの高次元情報を自動的に有用な特徴に変換できるため、現代の音声認識ではログメルスペクトログラムが広く使われています（例：Whisper、wav2vec2）。

    Aは逆の説明。Cはメルフィルタバンクを使うので誤り。Dは誤り（リアルタイム計算可能）。

    第8回　最新ASRモデル — Conformer / Whisperなど大規模End-to-End認識¶

    この回の資料

    • 📊 スライドを開く（HTML）
    • 📄 スライド（PDF）
    • 形式：オンライン同期回（Zoom・録画を後日公開）

    本日の到達目標¶

    1. End-to-Endモデルの概念と従来型との違いを説明できる
    2. CTC・Attention-based Encoder-Decoderの仕組みを理解する
    3. ConformerとWhisperのアーキテクチャ的特徴を説明できる
    4. OpenAI Whisperを使って実際に音声認識を行える
    5. 発展：CTCが「同じ答えになる経路の和」であること、アテンションが重み付き平均であることを、式から自分で説明できる

    進化の視点：学習量の差は、何を意味するか¶

    Conformer や Whisper のような大規模モデルは、数万〜数十万時間規模の音声で学習する。一方、子どもが言語を獲得するまでに触れる音声はその何桁も下である。それでも子どもは、雑音の中で、話者が変わっても、方言が違っても聞き取れるようになる。

    この差の説明としては、学習を効率化する生得的な制約、身体や視覚からの多様な手がかり、対話という能動的な学習の場などが挙げられる。どれか一つに決まっているわけではない。

    技術への接続：データを増やして精度を上げる方向と、少ないデータで学ぶ方向は、どちらも研究されている。低資源言語の音声認識は後者の問題である。

    問い：データを増やす以外に、精度を上げる道はあるか。

    スライド1: End-to-Endモデルとは¶

    従来型との比較¶

    項目 従来型（GMM-HMM時代） End-to-End
    構成 音響モデル＋言語モデル＋デコーダ 単一のニューラルネットワーク
    入力 音声特徴量（MFCC等） 音声波形 or メルスペクトログラム
    出力 音素列→単語列 直接テキスト
    学習 各モジュールを別々に訓練 エンドツーエンドで一括学習
    アライメント 必要（強制アライメント等） 不要（モデルが暗黙的に学習）

    End-to-End学習のメリット¶

    [入力: 音声波形]
         ↓
   [ニューラルネットワーク（1つのモデル）]
      ・音声の特徴を自動抽出
      ・音素への変換を暗黙的に学習
      ・言語的な文脈も考慮
         ↓
[出力: 文字列 / 単語列]

→ 学習データ: (音声, テキスト) のペアだけでOK！

    代表的なEnd-to-Endアーキテクチャ¶

    1. CTC（Connectionist Temporal Classification）
    2. Attention-based Encoder-Decoder（AED）
    3. RNN-T（Transducer）
    4. これらのハイブリッド

    スライド2: CTC（Connectionist Temporal Classification）の仕組み¶

    問題：長さが合わない¶

    音声フレーム数 \(T\)（例: 300フレーム）と出力文字数 \(L\)（例: 20文字）は一致しない。 どのフレームがどの文字に対応するかも事前には不明（アライメント問題）。

    CTCはこれをエレガントに解決する。

    CTCの核心：ブランクラベルと多対一マッピング¶

    出力アルファベットにブランクラベル \(\epsilon\) を追加する。

    CTC出力は各フレームで（文字 ∪ \(\epsilon\)）のいずれかを出力し、以下のルールでテキストに変換：

    1. 繰り返しをまとめる: aaa → a
    2. ブランクを除去: a_b__b → ab（_は\(\epsilon\)）
    例: 目標文字列 "cat"

あり得るCTC出力パス（すべて "cat" に対応）:
  c c a a t t (繰り返し除去→cat)
  c _ a _ t _ (ブランク除去→cat)
  _ c a t _ _ (ブランク除去→cat)
  c _ a a t t (繰り返し+ブランク除去→cat)

    CTC損失関数¶

    すべての有効なパスの確率の和を最大化する：

    \[\mathcal{L}_{\text{CTC}} = -\log P(Y \mid X) = -\log \sum_{\pi \in \mathcal{B}^{-1}(Y)} \prod_{t=1}^{T} p(\pi_t \mid X)\]

    前向き・後ろ向きアルゴリズムで効率的に計算可能。

    CTCの特徴¶

    • メリット: 単純、ストリーミング認識に向く（左から右へ処理可能）
    • デメリット: 条件付き独立性の仮定（各フレームの出力は他フレームに独立）、言語モデルが弱い
    導出①：CTC は「同じ答えになる経路を全部足す」ことでアライメントを消している

    問題は、どのフレームがどの文字に対応するか分からないことだった。CTC はこれを決めないことで解決する。

    フレームごとの出力を並べた \(\pi = (\pi_1, \ldots, \pi_T)\) を1本の経路と呼ぶ。各フレームの出力が互いに独立だと仮定すると、経路1本の確率は積で書ける。

    \[P(\pi \mid X) = \prod_{t=1}^{T} p(\pi_t \mid X)\]

    ここで \(\mathcal{B}\) を「繰り返しをまとめ、ブランクを除く」変換とする。目標 \(Y\) になる経路は1本ではなく、\(\mathcal{B}^{-1}(Y)\) という集合をなす（上の cat の例のように何通りもある）。これらは互いに排反な出力の仕方なので、目標が出る確率はそれらの和である。

    \[P(Y \mid X) = \sum_{\pi \in \mathcal{B}^{-1}(Y)} \prod_{t=1}^{T} p(\pi_t \mid X)\]

    損失はこの対数を取って符号を変えただけである。

    なぜこれで位置を教えなくてよいのか。 学習時に上げているのは「特定の1本の経路の確率」ではなく「正しい答えになる経路すべての確率の合計」である。どの経路で達成するかはモデルに任されている。 だから正解ラベルに時間位置を書き込む必要がない。これが「アライメント不要」の正体である。

    経路の数は \(T\) について指数的に増えるが、この和は前向き・後ろ向きアルゴリズムで効率よく計算できる。第7回の導出②とまったく同じ構造で、素朴に数え上げると爆発する和を、漸化式によって系列長に比例する計算に落としている。

    積に分解した1行目が、独立の仮定そのものである

    経路の確率を積に分解したところで、フレームごとの出力が互いに独立だと仮定している。デメリットとして挙げた「条件付き独立性の仮定」はここに現れる。文字どうしのつながりをモデル自身が表現できないので、言語モデルを外から足すことが多い。

    使った数学：独立な事象の積の法則と、排反な事象の確率の和（統計学Ⅱ第2回）。

    スライド3: Attention-based Encoder-Decoder¶

    アーキテクチャ概要¶

    [Encoder]                          [Decoder]
音声特徴量列                          テキスト列（自己回帰）
x₁, x₂, ..., xT                     y₀(BOS), y₁, y₂, ...
      ↓                                    ↓
  Encoder                         Decoder（Causal）
  （双方向）                        ← Cross-Attention ←┐
  h₁, h₂, ..., hT ────────────────────────────────────┘
                                         ↓
                                    y₁, y₂, ..., yL (EOS)

    Attention機構¶

    デコーダの各ステップで、エンコーダ出力のどの部分に注目するかを動的に決める。

    \[e_{ij} = \text{score}(\mathbf{s}_{i-1}, \mathbf{h}_j)\]
    \[\alpha_{ij} = \frac{\exp(e_{ij})}{\sum_{k=1}^{T}\exp(e_{ik})}\]
    \[\mathbf{c}_i = \sum_{j=1}^{T} \alpha_{ij} \mathbf{h}_j\]
    • \(\mathbf{s}_{i-1}\): デコーダの前ステップの隠れ状態
    • \(\mathbf{h}_j\): エンコーダの\(j\)番目の出力
    • \(\alpha_{ij}\): アテンションウェイト（どのフレームに注目するか）

    AEDの特徴¶

    • メリット: 長距離依存関係を捉えやすい、言語的な文脈を自然に組み込める
    • デメリット: 自己回帰デコーダは並列化困難、ストリーミングに向かない

    スライド4: Transformerの復習（Self-Attention）¶

    なぜTransformerが音声認識に強いか¶

    RNN（LSTM）の問題： - 長距離依存関係の学習が困難 - 逐次処理で並列化できない

    Transformerの解決策： - Self-Attentionですべての位置間の関係を直接計算 - 並列処理が可能

    Self-Attentionの計算¶

    入力列 \(\mathbf{X} \in \mathbb{R}^{T \times d}\) を Query, Key, Value に線形変換：

    \[\mathbf{Q} = \mathbf{X}\mathbf{W}_Q, \quad \mathbf{K} = \mathbf{X}\mathbf{W}_K, \quad \mathbf{V} = \mathbf{X}\mathbf{W}_V\]

    アテンションの計算：

    \[\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}\]

    音声での課題¶

    • 音声フレーム数は多い（100フレーム/秒 × 10秒 = 1000フレーム）
    • Self-Attentionの計算量は \(O(T^2)\) → 長い音声で計算コストが高い
    • Conformerはこの課題を解決する
    導出②：アテンションの正体は「重み付き平均」である

    スライド3の式を分解する。まず重みを作る部分はソフトマックスである。

    \[\alpha_{ij} = \frac{\exp(e_{ij})}{\sum_{k=1}^{T}\exp(e_{ik})}\]

    指数関数は必ず正なので \(\alpha_{ij} > 0\)。また分母が分子の総和そのものなので、

    \[\sum_{j=1}^{T} \alpha_{ij} = \frac{\sum_{j}\exp(e_{ij})}{\sum_{k}\exp(e_{ik})} = 1\]

    正で、足して1。つまり \(\alpha_{i1}, \ldots, \alpha_{iT}\) は確率と同じ形をしている。 そしてこれを値ベクトルに掛けて足したものが出力だった。

    \[\mathbf{c}_i = \sum_{j=1}^{T} \alpha_{ij}\, \mathbf{h}_j\]

    これは \(\mathbf{h}_1, \ldots, \mathbf{h}_T\) の加重平均にほかならない。重みがすべて等しければただの平均になり、1か所だけ1で残りが0ならその位置の値をそのまま取り出す。アテンションは、この両極のあいだを連続的に動ける「やわらかい選択」である。 行列で書いた \(\text{softmax}(\mathbf{Q}\mathbf{K}^\top/\sqrt{d_k})\mathbf{V}\) も、行ごとに見れば同じことをしている。

    使った数学：指数関数が正であること、総和の約分。

    導出③：なぜ \(\sqrt{d_k}\) で割るのか

    重みのもとになる値は、クエリとキーの内積である。

    \[\mathbf{q}\cdot\mathbf{k} = \sum_{m=1}^{d_k} q_m k_m\]

    \(q_m, k_m\) が互いに独立で平均0・分散1だとすると、各項 \(q_m k_m\) の分散は1になる。独立な確率変数の和の分散は加法的（統計学Ⅰ第6回）なので、

    \[\mathrm{Var}[\mathbf{q}\cdot\mathbf{k}] = \sum_{m=1}^{d_k} \mathrm{Var}[q_m k_m] = d_k\]

    標準偏差は \(\sqrt{d_k}\) である。次元が大きいほど内積は大きく振れる。

    振れが大きいと何が困るか。ソフトマックスは入力の差が大きいほど、最大の要素の重みが1に、残りが0に近づく。ほぼ1か0に張り付いた状態では、入力を少し動かしても出力がほとんど変わらない。つまり勾配がほぼ消え、学習が進まなくなる。

    そこで \(\sqrt{d_k}\) で割り、次元によらずスケールを一定に戻す。

    \[\mathrm{Var}\!\left[\frac{\mathbf{q}\cdot\mathbf{k}}{\sqrt{d_k}}\right] = \frac{d_k}{d_k} = 1\]

    数値で確かめる：平均0・分散1の乱数ベクトル20万組で内積の分散を測ると、\(d_k=8\) で 8.0、\(d_k=64\) で 63.8、\(d_k=512\) で 510.9 となり、いずれも \(d_k\) に一致する。標準偏差はそれぞれ 2.83、7.99、22.60 で、\(\sqrt{d_k}\)（2.83、8.00、22.63）と合う。この \(\sqrt{d_k}\) という一見ささいな定数は、分散の加法性から出てくる必然である。

    使った数学：分散の加法性と定数倍の規則（統計学Ⅰ第6回）。

    スライド5: Conformerとは何か¶

    提案の動機¶

    Transformerの強み: 大域的（長距離）な依存関係の捕捉
    CNNの強み: 局所的な構造（隣接フレームの音響パターン）の捕捉

    → 両方の良いところを組み合わせる！

    Conformerブロックの構造¶

    入力
 ↓
┌──────────────────────────────────┐
│  Feed-Forward Module (×½)        │  ← 位置ごとの非線形変換
├──────────────────────────────────┤
│  Multi-Head Self-Attention       │  ← 大域的な関係
├──────────────────────────────────┤
│  Convolution Module              │  ← 局所的なパターン
│    Point-wise Conv → Gated Act  │
│    → Depth-wise Conv → BN       │
│    → Point-wise Conv            │
├──────────────────────────────────┤
│  Feed-Forward Module (×½)        │  ← 位置ごとの非線形変換
└──────────────────────────────────┘
 ↓
出力（残差接続 + LayerNorm は各モジュールに）

    MacaronNetスタイル（半分サイズのFFNを前後に配置）。

    Conformerの性能¶

    Gulati et al. (2020, Google) の報告：

    モデル LibriSpeech test-clean WER LibriSpeech test-other WER
    Transformer 2.1% 4.9%
    Conformer (S) 2.1% 5.0%
    Conformer (M) 2.0% 4.6%
    Conformer (L) 1.9% 3.9%

    → Conformerは現在も多くのASRシステムのエンコーダとして採用されている。

    スライド6: Whisperの詳細¶

    Whisperとは¶

    Radford et al. (2022, OpenAI) が発表した大規模多言語音声認識モデル。

    主な特徴: - 680,000時間の多言語・多タスク音声データで学習（Web上から収集） - 99言語の音声認識、翻訳、言語識別を単一モデルで実現 - 教師あり学習（ラベル付き大規模データ）

    学習データの特徴¶

    680,000時間のデータ内訳（概算）:
┌─────────────────────────────────────────┐
│ 英語音声認識: 438,000時間               │
│ 多言語音声認識: 125,000時間（98言語）   │
│ 英語への翻訳: 117,000時間               │
└─────────────────────────────────────────┘
日本語: 約7,000時間相当が含まれる

    アーキテクチャ¶

    Encoder-Decoderアーキテクチャ（Transformerベース）:

    入力音声（30秒ウィンドウ）
   ↓ ログメルスペクトログラム（80チャネル）
[Convolutional Stem]
  2層Conv + GELU（時間次元を1/2に圧縮）
   ↓
[Transformerエンコーダ]
  Nブロック（モデルサイズによる）
   ↓ エンコーダ出力
[Transformerデコーダ]
  + 特殊トークンによるタスク制御:
    <|startoftranscript|>
    <|ja|>  ← 言語
    <|transcribe|> または <|translate|>  ← タスク
    <|notimestamps|> ← オプション
   ↓
[出力テキスト（自己回帰）]

    スライド7: Whisperの強み・弱み¶

    強み¶

    1. ゼロショット汎化: 見たことのないドメインやアクセントでも安定した性能
    2. 多言語・多タスク: 単一モデルで認識・翻訳・言語識別
    3. ロバスト性: Web収集データの多様性により騒音やアクセントへの耐性が高い
    4. タイムスタンプ: 単語レベルのタイムスタンプ出力も可能（large-v2以降）

    弱み¶

    1. ハルシネーション（幻覚）: 沈黙区間やノイズで存在しないテキストを出力することがある
    2. 固定30秒ウィンドウ: 長い音声は30秒に分割して処理するため、文脈が途切れる
    3. リアルタイム処理: 大きなモデルでは推論速度がリアルタイムに届かない場合がある
    4. 特定ドメインの専門用語: 一般ドメインに偏ったデータで学習されているため、医療・法律用語などは苦手なことがある

    Whisper vs 専門ASRシステム: 汎用性はWhisperが高いが、特定ドメインにチューニングされた専門モデルには劣ることもある。

    Step 5: Google Colabでマイク録音して認識¶

    # Google Colab でマイクから録音
from IPython.display import Javascript
from google.colab import output
from base64 import b64decode
import io
import soundfile as sf

# 録音用のJavaScriptコード
RECORD = """
const sleep = time => new Promise(resolve => setTimeout(resolve, time))
const b2text = blob => new Promise(resolve => {
  const reader = new FileReader()
  reader.onloadend = e => resolve(e.srcElement.result)
  reader.readAsDataURL(blob)
})
var record = time => new Promise(async resolve => {
  stream = await navigator.mediaDevices.getUserMedia({ audio: true })
  recorder = new MediaRecorder(stream)
  chunks = []
  recorder.ondataavailable = e => chunks.push(e.data)
  recorder.start()
  await sleep(time)
  recorder.onstop = async () => {
    blob = new Blob(chunks)
    text = await b2text(blob)
    resolve(text)
  }
  recorder.stop()
})
"""

def record_audio(sec=5):
    """指定秒数だけマイクから録音してwavファイルを返す"""
    print(f"{sec}秒間録音します... 話してください！")
    display(Javascript(RECORD))
    s = output.eval_js(f"record({sec * 1000})")
    b = b64decode(s.split(",")[1])
    audio_data, sample_rate = sf.read(io.BytesIO(b))
    sf.write("recorded.wav", audio_data, sample_rate)
    print("録音完了！")
    return "recorded.wav"

# 5秒間録音
audio_file = record_audio(sec=5)

# 認識
result = model.transcribe(audio_file, language="ja")
print("\n認識結果:", result["text"])

    演習：Whisperの誤りパターン分析¶

    課題¶

    Whisperに様々な音声を認識させ、誤りのパターンを分析する。

    実施手順¶

    以下の音声を自分のペースで用意・認識・分析する:

    1. 標準的な読み上げ音声 — 教科書の一節をゆっくり読む
    2. 速い発話 — 同じ文を早口で話す
    3. 騒音環境 — 周囲で雑音を出しながら話す（例: 手をたたく）
    4. 方言・アクセント — できれば方言話者に話してもらう（または訛りをつけて）
    5. 専門用語 — 音声処理の専門用語（「メルスペクトログラム」「HuBERT」等）を話す

    スライド（まとめ）: 今日のポイント¶

    1. End-to-End ASR: 音声→テキストを一括学習。アライメント不要。
    2. CTC: ブランクラベルにより長さ不一致問題を解決。前向き・後ろ向きアルゴリズムで効率計算。
    3. AED: Attention機構でエンコーダ出力を参照しながら自己回帰デコード。
    4. Conformer: Self-Attention（大域）+ Convolution（局所）の組み合わせで高性能エンコーダ。
    5. Whisper: 680,000時間の大規模多言語データでの教師あり学習。ゼロショット汎化が強み。
    6. 実習: WhisperをColabで実際に動かし、誤りパターンを分析した。

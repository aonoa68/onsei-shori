    第11回　自然言語処理との接続（NLUと音声）¶

    この回の資料

    • 📊 スライドを開く（HTML）
    • 📄 スライド（PDF）
    • 形式：動画回（オンデマンド動画＋CBTテスト）

    CBT・動画形式¶

    この回の学習目標¶

    1. 音声処理パイプライン（ASR → NLU → DM → NLG → TTS）の全体像を説明できる
    2. NLU（自然言語理解）の主要タスク（意図推定・スロット抽出・NER）を区別できる
    3. SLU（音声言語理解）がNLUとどう異なるかを理解できる
    4. 対話管理（Dialogue Management）のルールベース・機械学習アプローチを比較できる
    5. LLMと音声処理の統合の最新動向を把握できる
    6. PythonでSpeechRecognition・Whisper・transformersを使った実装ができる

    進化の視点：語と意味の結びつきは、どこまで恣意的か¶

    言語学では、語の形と意味の結びつきは恣意的だとされてきた。しかし、世界の言語の語彙を統計的に調べると、特定の意味に特定の音が偏る傾向が見つかる（Blasi ほか 2016, PNAS）。丸い形と「ブーバ」、尖った形と「キキ」の対応も、その一例である。

    近年は、この対応を音声そのものの性質から説明する研究がある。丸い物体と尖った物体は、ぶつかるときに異なるスペクトルと時間構造の音を出すため、環境の規則性の学習として説明できるという提案である（Scientific Reports 2022）。

    技術への接続：この回で扱う自然言語理解は、語と意味の対応をデータから学ぶ。学習された表現に、この非恣意性が現れるかを調べる研究も出てきている。恣意性を前提にする設計と、非恣意性を利用する設計は別物である。

    問い：新しい製品名を機械に考えさせるとき、音の印象をどう扱うか。

    スライド講義¶

    スライド1：音声処理パイプラインの全体像¶

    現代の音声対話システムは、複数のモジュールが直列に連結されたパイプラインで構成されています。

    音声入力
    ↓
[ASR] 音声認識（Automatic Speech Recognition）
    ↓ テキスト
[NLU] 自然言語理解（Natural Language Understanding）
    ↓ 意図・スロット・エンティティ
[DM]  対話管理（Dialogue Management）
    ↓ 行動指示・応答内容
[NLG] 自然言語生成（Natural Language Generation）
    ↓ テキスト応答
[TTS] 音声合成（Text-to-Speech）
    ↓
音声出力

    各モジュールの役割¶

    モジュール 入力 出力 例
    ASR 音声波形 テキスト 「東京から大阪まで新幹線を予約して」
    NLU テキスト 意図・スロット 意図：鉄道予約, 出発地：東京, 目的地：大阪, 交通手段：新幹線
    DM 意図・スロット・履歴 行動計画 日時が未確定 → 日時を質問
    NLG 行動計画 テキスト 「出発日時をお教えください」
    TTS テキスト 音声 合成音声で読み上げ

    パイプラインのエラー伝播¶

    重要な性質として、前段のエラーは後段にそのまま伝播します。

    ASR誤認識：「大阪」→「小阪」
         ↓
NLU：目的地：小阪（存在しない地名）
         ↓
DM：エラー処理 or 誤った応答

    このため、各モジュールの精度と、エラーを検出・回復する仕組みの両方が重要です。

    End-to-End（E2E）アプローチ¶

    最近では、パイプラインを使わずに音声入力から直接応答を生成するE2Eアプローチも登場しています。

    音声入力 → [大規模モデル（GPT-4o, Gemini等）] → 音声出力

    後のスライドで詳述します。

    スライド2：NLU — 自然言語理解とは¶

    NLUは、テキストの「意味」を機械が理解するための技術群の総称です。

    タスク1：意図推定（Intent Classification）¶

    ユーザーが「何をしたいか」を分類するタスク。

    例：スマートホームアシスタント

    入力：「リビングの電気を消して」
出力：Intent = TurnOff_Light, Room = リビング

入力：「今日の天気は？」
出力：Intent = GetWeather, Date = 今日

入力：「アラームを明日の7時にセット」
出力：Intent = SetAlarm, Time = 07:00, Date = 明日

    意図推定のアプローチ

    アプローチ 手法 特徴
    ルールベース 正規表現・キーワードマッチ 高速・解釈可能、カバレッジに限界
    機械学習 SVM, ロジスティック回帰 特徴量エンジニアリングが必要
    深層学習 BERT, RoBERTa等 文脈を理解、高精度
    LLMベース GPT, Claude等 Few-shot学習、柔軟

    タスク2：スロット抽出（Slot Filling）¶

    意図を実現するために必要な情報を発話から抽出するタスク。

    例：飛行機予約システム

    入力：「来週の金曜日に東京から福岡まで飛行機を予約したい」

スロット抽出結果：
{
  "departure_city": "東京",
  "destination_city": "福岡",
  "travel_date": "来週の金曜日",
  "transport_mode": "飛行機"
}

未充填スロット：
{
  "passenger_count": None,  → 質問が必要
  "seat_class": None        → 質問が必要（またはデフォルト値）
}

    スロット充填の難しさ - 「明後日」「来週末」等の相対的な時間表現の解決（時間正規化） - 省略・共参照：「そこから京都にも行きたい」（「そこ」＝東京） - スロット間の依存関係（往復便なら帰りの日付も必要）

    タスク3：固有表現認識（Named Entity Recognition / NER）¶

    テキスト中の固有名詞を「人名・地名・組織名・日時・数値」等にタグ付けするタスク。

    例：

    入力：「山田太郎さんが2024年3月に東京大学で発表した論文を探して」

NER結果：
[山田太郎]PER が [2024年3月]DATE に [東京大学]ORG で発表した論文を探して

    主要なエンティティタイプ

    タイプ 説明 例
    PER（Person） 人名 山田太郎、松本さん
    LOC（Location） 地名 東京、北海道、渋谷駅
    ORG（Organization） 組織名 トヨタ、文部科学省
    DATE/TIME 日時表現 3月15日、来週月曜
    NUM 数値・金額 3枚、5,000円

    スライド3：SLU — 音声言語理解との違い¶

    SLU（Spoken Language Understanding）は、音声処理特有の課題を含んだNLUの拡張です。

    NLUとSLUの違い¶

    観点 NLU SLU
    入力 書き言葉テキスト 話し言葉テキスト（ASR出力）
    句読点 あり なし（ASR出力は句読点なしが多い）
    フィラー なし あり（「えー」「あの」等）
    誤り テキスト入力ミス ASR誤認識（同音異義語等）
    文法 比較的正規 省略・倒置が多い

    話し言葉特有の課題¶

    フィラーと不流暢性

    書き言葉：「明日の会議室を予約したい」

話し言葉（ASR出力）：「えーと、あしたの、あのー、かいぎしつ、をーっと、よやくしたいんですけど」

    SLUは、このようなフィラー・繰り返し・言いよどみを正規化してNLUを適用します。

    ASR誤認識への耐性

    正しい発話：「新宿から渋谷まで」
ASR出力：「神宿から澁谷まで」（同音異義語による誤変換）

    SLUモデルは、ASR出力の不確実性（N-bestリスト・信頼度スコア）を考慮して理解を行います。

    音声からの直接的な情報¶

    SLUは音声波形からテキスト以上の情報を活用することもあります：

    • 韻律情報（Prosody）：ピッチ・強調・速度 → 感情・重要度
    • 話者情報：誰が話しているか（話者識別）
    • パラ言語情報：笑い声・ため息・感情

    スライド4：対話管理（Dialogue Management）¶

    対話管理（DM）は、会話の「流れ」をコントロールするモジュールです。ユーザーの意図を達成するためにどんな行動をとるかを決定します。

    DMの役割¶

    入力：NLUの出力（意図・スロット）＋対話履歴
出力：次の行動（質問する・検索する・予約する・応答する等）

    ルールベースDM¶

    if intent == "鉄道予約":
    if departure_city == None:
        action = "出発地を質問する"
    elif destination_city == None:
        action = "目的地を質問する"
    elif travel_date == None:
        action = "日時を質問する"
    else:
        action = "予約APIを呼び出す"

    利点：動作が予測可能、デバッグ容易、ドメイン知識が明示的に組み込める
    欠点：ルールの数が増えると管理困難、想定外の入力に弱い

    機械学習DM¶

    ベイズ的対話状態追跡（Bayesian DST）

    各スロットの充填状態を確率分布として管理：
{
  "departure_city": {"東京": 0.9, "とうきょう": 0.1},
  "travel_date": {"明日": 0.7, "明後日": 0.3}
}

    強化学習DM

    • 対話成功・ユーザー満足度を報酬として、最適な対話戦略を学習
    • 長期的な対話全体の最適化が可能
    • 大量のシミュレーションデータが必要

    対話状態トラッキング（Dialogue State Tracking / DST）¶

    ターン1：
ユーザー：「東京から大阪に行きたい」
State：{departure: 東京, destination: 大阪, date: ?, count: ?}

ターン2：
ユーザー：「来週の土曜」
State：{departure: 東京, destination: 大阪, date: 来週土曜, count: ?}

ターン3：
ユーザー：「2人で」
State：{departure: 東京, destination: 大阪, date: 来週土曜, count: 2}
→ 全スロット充填 → 予約処理へ

    スライド5：大規模言語モデル（LLM）との接続¶

    2022年以降、LLMの登場により音声対話システムのアーキテクチャが大きく変化しています。

    Whisper + LLM によるEnd-to-End対話¶

    従来のパイプライン型

    音声 → ASR(Whisper) → テキスト → NLU → DM → NLG → TTS → 音声

    LLM統合型

    音声 → ASR(Whisper) → テキスト → LLM(GPT-4等) → テキスト → TTS → 音声
                                     ↑
                            NLU・DM・NLGを統合

    LLMが担う機能 - 意図理解（NLU）：Few-shotプロンプトで多様な意図を処理 - 文脈管理（DM）：プロンプトに対話履歴を渡すことで文脈を保持 - 応答生成（NLG）：自然な文体で応答を生成

    GPT-4o の音声モード（2024〜）¶

    OpenAI GPT-4oは、音声を中間テキストに変換せず、直接音声から音声へ処理する能力を持っています。

    従来：音声 → テキスト変換 → LLM → テキスト → 音声合成
GPT-4o：音声 → [GPT-4o（マルチモーダル）] → 音声

    革新的な点 - 韻律・感情を音声から直接認識・表現 - テキスト変換による情報ロスがない - 平均応答遅延：約320ミリ秒（従来の半分以下） - 笑い・息遣い等のパラ言語情報の認識と生成

    Google Gemini の音声機能¶

    • Gemini 1.5 Pro/Flash：音声ファイルを直接入力として受け付け
    • 長時間音声（最大9.5時間）の理解・要約
    • 音声からの多言語翻訳

    LLM統合のトレードオフ¶

    観点 パイプライン型 LLM統合型
    精度制御 各モジュールで個別チューニング可 LLMに依存
    解釈可能性 各ステップを確認可能 ブラックボックス化
    コスト 比較的低 API利用料が高い
    柔軟性 ドメイン外の発話に弱い 幅広い対話に対応
    レイテンシ 各モジュールの遅延が積算 E2Eで削減可能
    プライバシー オンデバイス化しやすい クラウド依存が多い

    スライド6：自然言語生成（NLG）と音声合成（TTS）¶

    NLG（Natural Language Generation）¶

    対話管理の出力（行動・情報）を自然な文に変換するモジュールです。

    テンプレートベース

    templates = {
    "weather_response": "今日の{city}の天気は{weather}です。最高気温は{temp}度です。",
}
# 例：「今日の東京の天気は晴れです。最高気温は25度です。」

    ニューラルNLG

    • Seq2Seq モデル・Transformer による自然な応答生成
    • LLM（GPT等）による高品質な応答生成

    NLGの評価指標

    指標 説明
    BLEU 参照文との n-gram一致率（機械翻訳由来）
    METEOR 語彙的多様性を考慮したBLEUの改良版
    BERTScore BERT埋め込みの類似度
    人手評価 自然さ・流暢さ・情報の正確さを人が評価

    TTS（Text-to-Speech）の最新動向¶

    世代 手法 品質
    第1世代 フォルマント合成 ロボット的
    第2世代 波形接続合成（統計的） 自然だが単調
    第3世代 WaveNet/Tacotron2 高品質、人間に近い
    第4世代 VITS/VALL-E/SoundStorm 数秒の音声でクローン可能、感情表現豊か

    スライド7：評価指標¶

    音声対話システム全体の評価には、複数の指標を組み合わせることが重要です。

    自動評価指標¶

    指標 対象モジュール 計算方法
    WER（Word Error Rate） ASR (S+D+I) / N × 100%
    Intent Accuracy NLU 正解intent数 / 全テスト数
    Slot F1 NLU スロット抽出のF1スコア
    BLEU / ROUGE NLG n-gram一致率
    MOS（Mean Opinion Score） TTS 1〜5点の主観評価の平均

    対話レベルの評価指標¶

    指標 説明
    Task Completion Rate（TCR） タスクを完了できた会話の割合
    Average Turns per Dialogue 1タスクあたりの平均ターン数（少ないほど効率的）
    Dialogue Success Rate ユーザーが満足してタスクを完了できた割合
    F1 on Joint Accuracy 全スロットが正確に充填された対話の割合（DST評価）

    人手評価（Human Evaluation）¶

    自動指標では捉えられない側面の評価： - 自然さ（Naturalness）：応答は人間らしいか - 一貫性（Coherence）：対話の流れは矛盾していないか - 情報正確性（Factuality）：生成した情報は正しいか - 安全性（Safety）：有害・差別的な応答はないか

def recognize_from_microphone():
    """マイクから音声を録音してGoogle Speech Recognition APIで認識する"""
    recognizer = sr.Recognizer()

    with sr.Microphone() as source:
        print("話してください...")
        # 周囲のノイズに合わせてエネルギー閾値を自動調整
        recognizer.adjust_for_ambient_noise(source, duration=1)
        audio = recognizer.listen(source, timeout=5, phrase_time_limit=10)
        print("認識中...")

    try:
        # Google Speech Recognition API（クラウド）
        text = recognizer.recognize_google(audio, language="ja-JP")
        print(f"認識結果：{text}")
        return text
    except sr.UnknownValueError:
        print("音声を認識できませんでした")
        return None
    except sr.RequestError as e:
        print(f"APIエラー: {e}")
        return None

def recognize_from_file(audio_file_path: str) -> str | None:
    """音声ファイルからテキストを認識する"""
    recognizer = sr.Recognizer()

    with sr.AudioFile(audio_file_path) as source:
        audio = recognizer.record(source)

    try:
        text = recognizer.recognize_google(audio, language="ja-JP")
        return text
    except sr.UnknownValueError:
        return None

# Part 2: 簡易意図分類器
# ============================================================

# 意図とキーワードの対応表（ルールベース）
INTENT_PATTERNS = {
    "天気確認": ["天気", "気温", "雨", "晴れ", "曇り", "明日の空", "今日の気候"],
    "時刻確認": ["時間", "何時", "時刻", "今何時"],
    "アラーム設定": ["アラーム", "目覚まし", "起こして", "タイマー"],
    "ミュージック再生": ["音楽", "曲", "再生", "プレイ", "聴かせて", "歌"],
    "電気操作": ["電気", "ライト", "照明", "消して", "つけて", "明るく", "暗く"],
    "検索": ["検索", "調べて", "教えて", "何", "どこ", "いつ", "誰"],
}

# スロット抽出パターン（簡易版）
LOCATION_KEYWORDS = ["東京", "大阪", "札幌", "福岡", "名古屋", "京都", "横浜", "神戸"]
TIME_KEYWORDS = {
    "今日": 0, "明日": 1, "明後日": 2,
    "今週": 0, "来週": 7,
    "午前": "AM", "午後": "PM", "朝": "morning", "夜": "night"
}

def classify_intent(text: str) -> dict:
    """
    テキストから意図を分類し、スロットを抽出する

    Parameters
    ----------
    text : str
        認識されたテキスト

    Returns
    -------
    dict
        intent, confidence, slots を含む辞書
    """
    result = {
        "text": text,
        "intent": "不明",
        "confidence": 0.0,
        "slots": {}
    }

    if not text:
        return result

    # 意図スコアの計算（マッチしたキーワード数を正規化）
    intent_scores = {}
    for intent, keywords in INTENT_PATTERNS.items():
        score = sum(1 for kw in keywords if kw in text)
        if score > 0:
            intent_scores[intent] = score / len(keywords)

    if intent_scores:
        best_intent = max(intent_scores, key=intent_scores.get)
        result["intent"] = best_intent
        result["confidence"] = intent_scores[best_intent]

    # 場所スロットの抽出
    found_locations = [loc for loc in LOCATION_KEYWORDS if loc in text]
    if found_locations:
        result["slots"]["location"] = found_locations[0]

    # 時間スロットの抽出
    found_times = [kw for kw in TIME_KEYWORDS if kw in text]
    if found_times:
        result["slots"]["time"] = found_times[0]

    return result

def speech_to_sentiment(audio_file: str) -> dict:
    """
    音声ファイルを受け取り、テキスト変換と感情分析を行う

    Parameters
    ----------
    audio_file : str
        音声ファイルのパス（.wav, .mp3, .m4a等）

    Returns
    -------
    dict
        transcript（認識テキスト）、language（検出言語）、
        sentiment（感情ラベル）、score（信頼度）を含む辞書
    """
    result = {}

    # ステップ1: 音声認識（Whisper）
    print(f"音声を認識中: {audio_file}")
    transcription = whisper_model.transcribe(
        audio_file,
        language="ja",       # 日本語を指定（Noneにすると自動検出）
        fp16=False,          # CPU使用時はFalse
        verbose=False
    )

    transcript = transcription["text"]
    detected_language = transcription["language"]
    print(f"認識テキスト: {transcript}")
    print(f"検出言語: {detected_language}")

    result["transcript"] = transcript
    result["language"] = detected_language
    result["segments"] = [
        {
            "start": seg["start"],
            "end": seg["end"],
            "text": seg["text"]
        }
        for seg in transcription.get("segments", [])
    ]

    # ステップ2: 感情分析（transformers）
    if transcript and len(transcript.strip()) > 0:
        print("感情分析中...")
        # 長いテキストは512トークンで切り捨て
        text_for_sentiment = transcript[:512]
        sentiment_result = sentiment_analyzer(text_for_sentiment)[0]

        result["sentiment"] = sentiment_result["label"]
        result["sentiment_score"] = sentiment_result["score"]

        # ラベルの日本語化
        label_map = {
            "positive": "ポジティブ",
            "negative": "ネガティブ",
            "neutral": "ニュートラル",
            "POSITIVE": "ポジティブ",
            "NEGATIVE": "ネガティブ",
            "NEUTRAL": "ニュートラル",
        }
        result["sentiment_ja"] = label_map.get(
            result["sentiment"], result["sentiment"]
        )
    else:
        result["sentiment"] = "N/A"
        result["sentiment_score"] = 0.0
        result["sentiment_ja"] = "分析不可"

    return result

def analyze_multiple_files(audio_files: list) -> list:
    """複数の音声ファイルを一括処理する"""
    results = []
    for audio_file in audio_files:
        print(f"\n{'='*50}")
        if os.path.exists(audio_file):
            result = speech_to_sentiment(audio_file)
            results.append(result)
        else:
            print(f"ファイルが見つかりません: {audio_file}")
    return results

    問題1¶

    音声対話パイプラインにおいて、「自然言語理解（NLU）」の主な役割として最も正確に説明しているものはどれか。

    a) 音声波形をテキストに変換する
    b) 対話の文脈を追跡して次のシステム行動を決定する
    c) テキストの意味を解析し、意図やスロットを抽出する
    d) テキストを自然な音声に変換する

    解答と解説 **正解：c)** **解説**： a) は ASR（音声認識）の役割です。 b) は DM（対話管理）の役割です。 c) が NLU の正しい説明です。NLU はテキストを意味的に解析し、ユーザーの「意図（Intent）」と、その意図を実現するための具体的な情報「スロット（Slot）」を抽出します。例：「明日の東京の天気を教えて」→ 意図：天気確認、スロット：日付=明日、場所=東京。 d) は TTS（音声合成）の役割です。

    問題2¶

    SLU（Spoken Language Understanding）が NLU と異なる主な理由はどれか。

    a) SLU は画像も同時に処理できる
    b) SLU は ASR の出力（話し言葉テキスト）を扱うため、句読点の欠如・フィラー・認識誤りへの対応が必要だから
    c) SLU は文書検索システム専用だから
    d) SLU は感情分析のみを行うモジュールだから

    解答と解説 **正解：b)** **解説**： NLU は書き言葉テキスト（きれいに整形された文）を入力として想定することが多いですが、SLU は ASR の出力を入力とします。ASR の出力には（1）句読点がない、（2）「えーと」「あのー」等のフィラーが含まれる、（3）同音異義語による誤認識がある、といった特徴があります。SLU はこれらを考慮したうえで意味理解を行います。

    問題3¶

    エッジ推論における「知識蒸留（Knowledge Distillation）」の説明として正しいものはどれか。

    a) モデルのパラメータを低精度（int8等）に変換することでメモリを削減する技術
    b) 重要度の低いパラメータ（ニューロン）を削除することでモデルを軽量化する技術
    c) 大規模な教師モデルの出力確率分布を使って、小規模な生徒モデルを訓練する技術
    d) 複数のモデルを組み合わせて精度を向上させるアンサンブル学習の一種

    解答と解説 **正解：c)** **解説**： a) は量子化（Quantization）の説明です。 b) はプルーニング（Pruning）の説明です。 c) が知識蒸留の正しい説明です。大規模な「教師モデル」の出力確率分布（Soft Labels）を教師信号として、小規模な「生徒モデル」を訓練します。ハードラベル（正解クラスのみ1）ではなくソフトラベル（各クラスの確率分布）を学ぶことで、少ないパラメータでも高い汎化性能が得られます。 d) はアンサンブル学習の説明です。

    問題4¶

    GPT-4oの音声モード（2024年〜）が従来の音声対話システムと比較して特徴的な点はどれか。最も適切なものを選べ。

    a) テキストを介さずに音声から音声へ直接処理するため、韻律・感情情報を損失なく扱える
    b) 音声認識精度が100%になった
    c) インターネット接続なしで動作するオンデバイスシステムである
    d) 日本語のみに特化した音声処理システムである

    解答と解説 **正解：a)** **解説**： a) が正しい。GPT-4oは「音声 → テキスト → LLM → テキスト → 音声」という従来のパイプラインを経ず、音声を直接入力・出力として処理するマルチモーダルモデルです。これにより、テキスト変換時に失われていた韻律・感情・息遣いといったパラ言語情報も理解・生成できます。 b) 音声認識精度100%は現時点では達成されていません。 c) GPT-4oはクラウドベースのシステムです。 d) GPT-4oは多言語対応のシステムです。

    問題5¶

    音声対話システムの評価指標に関する次の記述のうち、誤っているものはどれか。

    a) WER（Word Error Rate）は音声認識の誤り率を示し、低いほど認識精度が高いことを意味する
    b) Task Completion Rate（TCR）は、対話全体でタスクを完了できた会話の割合を示す
    c) BLEU スコアは NLG（自然言語生成）の評価に使われ、生成文と参照文のn-gramの一致を測る
    d) WER が 0% であれば、対話システム全体の性能も必ず最高になる

    解答と解説 **正解：d）（誤りの記述）** **解説**： d) が誤りです。WER が 0%（音声認識が完璧）であっても、NLU・DM・NLG・TTS の各モジュールに問題があれば対話システム全体の性能は低くなります。例えば、ASR が完璧でも NLU が誤った意図を推定すれば正しい応答はできません。音声対話システムはパイプラインで構成されており、**全モジュールの連携品質が重要**です。 a)〜c) はすべて正しい記述です。

## 進化の視点：発話・聴覚から学ぶ工学と、その違い

この授業では、発話と聴覚のしくみ、デジタル化、特徴量、統計・大規模モデル、評価、UX、言語・認知、社会的影響を学んできた。

**音声技術には発話・聴覚の知見を参照した部分があるが、人間の仕組み全体の再現ではない。** 次の点を分けて振り返る。

| 比較するもの | 何を参照し、何を区別するか |
|---|---|
| ソース・フィルタモデル | 音源と声道によるフィルタリングを分ける近似。発話器官全体や相互作用を完全に再現するモデルではない（第2回） |
| メル尺度 | 音の高さの知覚に関する心理尺度を参照する。聴覚の周波数分解能や臨界帯域をそのまま表す尺度ではない[^mel] |
| 学習経験 | モデルの音声学習時間と、人間の言語・視覚・社会的な経験は、そのまま同じ単位で比較できない |
| 評価 | WER／CERは文字列の誤りを測る。意味理解・意図の推定・人間の知覚体験は別に測る必要がある（第9・12回） |

人間が常に意味だけを聞くわけでも、工学の評価が文字列だけに限られるわけでもない。比較対象と課題をそろえて、得られた結果の範囲を示す。

**最終発表への問い**：あなたのテーマでは、発話・聴覚について何を仮定し、どの性質を測っているか。その仮定で説明できることと、説明できないことは何か。

### 2. 技術の仕組みと、利用への広がり

**仕組みを異なる粒度で説明する**

| 粒度 | 例 |
|---|---|
| 信号 | 波形サンプル、周波数、振幅 |
| 表現 | スペクトログラム、MFCC、学習された特徴 |
| モデル | HMM、CNN、RNN、Attention、Transformer |
| システム | 音声の入力から文字列や応答を得る処理全体 |
| サービス | APIやアプリで、誰が何をできるようにするか |

すべてのシステムがこの順で独立した部品を持つわけではない。End-to-End学習では複数の処理を一緒に最適化する場合もある。

**利用への広がりを考える**

認識・生成・対話という課題、個人の操作と社会的な利用、技術的な性能と倫理的な影響を結びつける。これらは互いに対立する一つの軸ではなく、同じシステムを評価する複数の観点である。

### 3. キーコンセプトの整理

**振り返りたい10のキーワード**

| # | キーワード | 説明 |
|---|-----------|------|
| 1 | MFCC | メル帯域のエネルギー等に対数を取り、DCTで得る代表的な音響特徴。次元数や設定を明示する |
| 2 | HMM | 隠れ状態の遷移と観測を確率的に表すモデル。GMMやDNNとの組合せもある |
| 3 | CTC | フレームと出力ラベルの対応が未指定でも、複数の整列を足し合わせて系列を学習する方法 |
| 4 | Attention／Transformer | Attentionは情報を重みづけて集約する仕組み。Transformerはそれを使うモデル構造 |
| 5 | Whisper | 大量の音声・テキスト対で学習した多言語ASRモデル群。性能は言語・条件で異なる |
| 6 | TTS／Voice Conversion | テキストからの音声合成／発話内容を保ちながら音声特性を変える課題 |
| 7 | GAN・拡散・フローマッチング | 音声生成にも使われる学習・生成の方式。TTS・VCという課題の分類とは別 |
| 8 | 話者照合（ASV） | 入力音声が、登録された対象話者のものかを判定する課題。声の類似だけで本人確認全体は保証しない |
| 9 | バイアス | 集団や利用条件により生じる偏りを検証する論点。データ・モデル・評価・利用を調べる |
| 10 | Deepfake／ASVspoof | 本物らしい生成・加工音声など／偽造検出・話者照合を共通条件で評価する枠組み |

MFCCの計算とCTCは原資料、Whisper・ASVspoofは原論文・公式評価計画も確認する。[^mfcc][^ctc][^whisper][^asvspoof]

### 6. テーマA — 音声特徴量分析レポート

**概要**

自分で収録した音声（または許可を得た音声）をMFCC等の特徴量で分析し、分析結果とその解釈を報告する。

**内容の例**

- 自分の声・友人の声・異なる感情で発話した音声を比較
- 日本語の母音・子音のスペクトル特性の分析
- 同じ音声に雑音を加えたときの特徴量の変化（認識精度まで比較する場合はテーマBの評価方法も参照）

**使用ツール（推奨）**

- Python（librosa, numpy, matplotlib）
- Praat（音声分析ソフトウェア、無料）
- Google Colab（GPU不要の演習で使用した環境）

**成果物の例**

- 分析コード + 結果のグラフ
- レポート（4,000〜6,000字程度）
- 発表用スライド（10〜15枚を目安）

**難易度目安**：★★★☆☆（中程度）  
**プログラミングが必要**：はい（基礎レベル）

### 7. テーマB — Whisperを使った多言語音声認識の精度比較

**概要**

OpenAI の Whisper を使って、複数の言語・方言・話者属性（性別・年齢等）での音声認識精度を比較する。

**比較の切り口例**

- 言語別（英語 vs. 日本語 vs. スペイン語 vs. アラビア語等）
- 方言別（標準語 vs. 関西弁 vs. 東北方言等）
- 話者属性別（年齢・ジェンダー等）。属性の記録方法を示し、声から本人の属性を推測して割り当てない
- 音声品質別（クリーン音声・雑音付加・帯域制限・コーデック圧縮）。サンプルレートと圧縮方式を区別する

**考察のポイント**

- 精度差について、データ・モデル・語彙・録音・評価条件のどの仮説を検証できるか？
- バイアスの視点から、観察されたことと原因の推測をどう区別できるか？
- どのような改善が考えられるか？

**使用ツール**

- Python（openai-whisper ライブラリ）
- Google Colab（GPU使用可）
- 使用条件を確認した公開音声データセット（例：[Common Voice](https://commonvoice.mozilla.org/about)、英語朗読の[LibriSpeech](https://www.openslr.org/12)）。言語・録音方式の異なるデータを比べる場合は、その違いも示す

**難易度目安**：★★★★☆（やや高め）  
**プログラミングが必要**：はい（中級レベル）

### テーマA 詳細：音声特徴量分析レポート

**課題の目的**

音声の物理的特徴量（MFCC・スペクトログラム等）を実際に計算・可視化し、音声の性質を定量的に分析する能力を示す。

**最低要件**

- [ ] 自ら収録した音声（または適切にライセンスされた音声）を使用
- [ ] MFCC（課題要件として最低13次元）の計算と可視化。13は必須の理論定数ではなく、0次係数を含めるかも明記
- [ ] 比較対象を2種類以上設定（例：異なる話者、異なる感情、異なる環境）
- [ ] 特徴量の計算方法と設定（サンプルレート、窓長・ホップ長、メル帯域、対数・DCT、次元数）の説明
- [ ] 結果の考察（差の原因について、観察と仮説を分けて説明）

**推奨追加要素**

- メルスペクトログラムの可視化
- ピッチ（基本周波数）の時系列分析
- 雑音の影響の定量化

### テーマB 詳細：Whisperを使った多言語音声認識の精度比較

**課題の目的**

実際に音声認識システムを動かし、条件を変えて精度を比較することで、音声認識の性能要因とバイアスへの理解を深める。

**最低要件**

- [ ] Whisper（または同等の音声認識システム）を用いた実験の実施
- [ ] 比較条件を最低2種類設定し、明確に定義（言語・方言・話者属性・音声品質など）
- [ ] 正解テキストを用意し、正規化と分かち書きの方針を明記
- [ ] WERまたはCERを計算し、モデルの版・設定、話者数・音声量を記録
- [ ] 結果の考察（原因についての仮説と確認できたことを分ける）
- [ ] 社会的含意の考察（誰にどんな利用上の負担が生じ得るか）

**WER（Word Error Rate）の計算方法**

参照文が1語以上ある場合：

$$
\mathrm{WER}=\frac{S+D+I}{N},\qquad
\mathrm{WER}[\%]=100\frac{S+D+I}{N}
$$

- $S$：単語の置換数、$D$：単語の削除数、$I$：単語の挿入数
- $N$：**参照文の単語数**。モデル内部のサブワードトークン数とは限らない
- CERは同様に文字単位で計算する

単語の区切りや表記の正規化をそろえて比較する。挿入が多ければWERは100%を超え得る。参照文が空の場合は、この式の分母が0になるため、無音時の誤出力などを別に報告するか、評価ライブラリの規約を明示する。[^jiwer]

異なる言語のWERを並べるときは、語の区切りやデータの内容も異なることを考慮する。音声認識の文字列評価だけで、意味理解や利用者への影響まで測定したことにはならない。

## 授業全体のまとめ：音声処理と認識が拓く世界

**歴史を、条件つきの研究成果として読む**

- **1970年代**：HARPYなどで、語彙や文法などの条件を定めた連続音声認識の研究が行われた。「数語程度しか認識できなかった」と一律に説明しない[^harpy]
- **1980〜1990年代**：HMMなどの統計的なモデルが発展。どの語彙・話者・課題での成果かを確認する
- **2010年代**：深層ニューラルネットワークを使う音響モデルやEnd-to-End方式が発展した[^dnn]
- **2020年代**：Whisperなどで大規模な学習と多言語の評価が進んだ。各言語・録音条件で同じ性能が出るという意味ではない[^whisper]

**実現した機能と、利用時に検証すること**

| 実現している機能の例 | どこまで働くかを確認する観点 |
|-------------|-------------------|
| 指定された条件での音声認識 | 未知の話者・雑音・方言、文字列の正確さと利用上の負担 |
| 自然さを高めた音声合成 | 読み・韻律・話者類似性、利用目的・同意・権利 |
| 短い参照音声を使う話者模倣 | 事前学習、対象言語・音声条件、検出と本人確認 |
| 条件に応じたリアルタイム処理 | 遅延、計算資源、誤りへの対応、性能差 |

「解決済み」と「未解決」を一つの固定した境界で分けず、具体的な利用条件と測定結果で評価する。
